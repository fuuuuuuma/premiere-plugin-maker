## 症状

- 公開リポジトリの補正用の辞書・メモ・参照資料に、個人名・チャンネル名・営業の情報が平文で入っていた。3 コミット分が公開済みだった。
- 来歴のコメントに、利用者のホームフォルダの絶対パス（Mac のユーザー名入りのもの）が入っていた。2 回起きた。
- 配布する初期辞書 13 件のうち 1 件が、個人の人名の補正だった。

## 原因

配布用のリポジトリに、個人の運用データを同居させていた。取り込みの同期スクリプトが、来歴のパスをそのまま記録した。

## 直し方

1. 個人の設定は、`config/corrections.local.json` のような別ファイルに分ける（`.gitignore` に入れ、`.example` を用意する）。起動時にマージする。
2. 来歴のパスは `~` に置き換える。個人のエントリは削除する。
3. 公開済みの履歴は `git filter-repo` で書き換える。事前に bundle とフルコピーで退避し、`--replace-text` と `--message-callback` の 2 パスで行い、実行中の未コミットの変更は `git stash push -u` で避ける。

## 再発防止

- 配る側を全て走査するテスト（個人のパスが無いこと）を置く。
- 公開前に、`git log --all -p | grep` で個人名を探し、秘密が 0 件であること、例文の実在の名前を置き換えたこと、古い表記を一掃したことを確かめる。
- デプロイの直前に、`ls -la` で更新時刻を見て、見覚えのないファイルは全文を読む。別のセッションが作った未確認のファイルが一緒に公開された事故があった。

## 出どころ

- Cut & SRT と関連プロジェクトの作業記録（2026-07-13〜09-27）
