## 症状

同じ版数のまま作り直して入れ直しても、変更が反映されない。応答しているサーバーが再起動もされず、プロセスの起動時刻（`ps -o lstart`）が前日のまま、半日気づかなかった。Windows では、導入先のファイルを手で直すとハッシュ（SHA-256）が合わずに止まった。

## 原因

インストーラは、`runtime/<版>` のフォルダが既にあると「上書きしません」と言って、古い物を使い続ける。これは更新が壊れにくいようにする設計だが、同じ版数では更新が届かないことを意味する。

## 直し方

1. 導入先の `runtime/<版>` を `mv` で退避する。
2. インストーラを `--yes` 付きで実行し、常駐を再起動して（`launchctl kickstart -k ...`）、状態確認の応答で版数を確かめる。
3. 利用者に配るなら、版を上げる。上げない場合は、入れ直し手順（先にサーバーを uninstall し、パネルも削除する）をガイドに書く。

## 再発防止

- 導入先を作業ブランチと `cmp` で比べる。この比較で、配布物に入れ忘れたファイル（ある送信タブのファイル）が見つかり、配布物のテストが止める形にした。
- 版数を上げる条件（両方の機種に関わる変更だけ上げる、など）と、同じ版では更新が届かない仕組みをセットで決める。
- Windows の入れ直し案内は未検証。
