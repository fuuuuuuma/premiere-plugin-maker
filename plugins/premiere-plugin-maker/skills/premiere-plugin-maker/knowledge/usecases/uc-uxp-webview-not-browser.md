## 症状

パネルの中の埋め込みブラウザ（Web タブ）で、すべてのページ遷移が拒否される（loaderror）。戻る・進む・再読込ができない。ファイルのダウンロードも失敗する。

## 原因

1. `webview.domains` に `"all"` や `["all"]` を書く、またはキーを省略すると、manifest の検査は通るが、実行時にすべての遷移が無言で loaderror になる（公式の文書では有効な値だが、実装されていない）。
2. `https://*.example.com` は、サブドメインのない裸のドメインには一致しない。
3. トップレベルドメインのワイルドカード（`https://*.com`）は受け付けられ、何階層もあるサブドメインにも一致する。
4. 戻る・進む・再読込の API が無い。
5. 添付ファイル（attachment）の応答は実行できず loaderror になり、ページとのメッセージのやりとりも使えない。

## 直し方

1. 主要なトップレベルドメイン 76 種を並べて、実質すべて開放にする。
2. 戻る・進む・再読込は、URL バーと「開く」「再読込」のボタンで代替する。
3. 失敗した遷移の URL は、プラグイン側の fetch でダウンロードフォルダーに保存する。
4. ログインが要るファイルは、WebView のログインの状態を共有しないので保存できない。その場合は、外部のブラウザを開くボタン（`shell.openExternal`）へ案内する。

## 再発防止

- UDT のデバッグで、開発者コンソールから webview 要素を直接評価するのが最も速い。
- `[browser]` の接頭辞つきのログを UXP のログから grep する。
- 許可するドメインは、公式の文書の「有効な値」を信じず、実機で確かめる。

## 出どころ

- Cut & SRT の実機デバッグの記録（Premiere 26.3、v0.9.20、2026-07-18 / 07-28）。画像のダウンロードの成功を確認した
- ログインが要るファイルを保存できない点は、実機デバッグ中の判断と、実装を読んだだけで実機未確認とする記録が食い違う。キットは、外部ブラウザへ案内する側に合わせた
