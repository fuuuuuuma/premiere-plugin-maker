## 症状

- 古い導入ガイドを配ると、受け取った人が混乱する。
- 「困ったとき」の表が実際のエラーと食い違った（gemini の行が古い文言で、antigravity の行が無かった）。
- 紹介のページが未実装の機能をうたっていた。
- 配布用の README に、確かめていない範囲の断定があった。

## 原因

人が手で書く表・紹介文・README は、エラー文言の唯一の出どころ（`messages.py` の「症状・なぜ・次の一手」）や、実装とは別に更新される。設計書や記憶から書けてしまう。

## 直し方

1. 機能・挙動・エラー文言を変えたら、同じコミットで該当ページ・変更履歴・「困ったとき」の表を更新する。
2. 実際にユーザーへ出るエラー文字列を洗い出し、表と突き合わせる（修正 1・追加 5、全 32 行）。
3. 紹介文の機能は、対応する関数や分岐を指さしてから書く。未確認の範囲（Windows など）は、未確認と明記する。

## 再発防止

- `file://` で実際に描画し、行数・セル数・コンソールのエラー 0・旧文言が消えたことを確かめる。
- 未実装の語が混ざらないよう、テストで見張る（例: 該当ページに「MCP」が含まれないこと）。
- 配布の前に、事実確認と誇張の検出（レビューの担当）を通す。

## 出どころ

- Cut & SRT の引き継ぎ記録と作者の開発メモ（2026-07-19〜10-02、v0.4.0〜v0.13.0）。配布向け README の言い切りは 2 回、レビューで指摘された。更新のルールは記述のみで、配布先での確認は無い。
