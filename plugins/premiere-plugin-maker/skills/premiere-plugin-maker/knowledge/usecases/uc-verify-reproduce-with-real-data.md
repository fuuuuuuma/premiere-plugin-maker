## 症状

- テスターの実際の XML が手元に無い間は、「レートの混在」「真因は書き出し側」が推定の止まりだった。
- 失敗の報告に、すでに修正済みの古いエラー文言が並んでいた。

## 原因

- 実データを回収できなかった。
- 報告された環境に、古い版や古い依存のスクリプトが残っていた。

## 直し方

1. 実際の XML と実素材を入手する。
2. 実際の fps（29.998）と、XML のすべての `<rate>`（29）を突き合わせる。
3. 赤いバッジの数字を `round(pproTicks 秒 × 実 fps) − in` で再現し、真因を確定する（v0.7.7）。
4. エラー文言を現行のものと突き合わせ、報告者が使っている版を逆算する。

## 再発防止

- テスターに、実際の XML・実素材・出力の SRT・文字起こしのログを依頼する。
- 回収できない間は、結論に「推定」と書く。
- エラー文言を変えた版を記録しておく（版の特定に使える）。

## 出どころ

- Cut & SRT の引き継ぎ記録（2026-07-19〜07-20、v0.4.1〜v0.7.7）。v0.7.7 は実際の XML と素材で再現した。版の逆算は推定。v0.7.6 の「確証は無い」は v0.7.7 で確証に変わった。
