## 症状

Windows でだけ、AI に改行を任せる処理が「出力が原文と一致しません」で失敗した（長さの比が 0.08〜0.52）。短い文章なら正常に動く。

## 原因

`*.cmd` で配られる外部コマンド（npm で入れたもの）は、`cmd /c` を経由して起動される。cmd.exe は、引用符の中でも、改行や `<>&|%` を解釈し直す。15KB を超え、改行が 146 個あるような長い指示は、1 行目しか届かず、しかも終了コード 0 で返ってくる。

## 直し方

本文を引数から外す。コマンドごとに入力の経路が違う。

- 標準入力を読む形（`-` を指定、または `-p` の後に stdin）に変える。
- ファイルから読むオプション（`--prompt-file` など）に変える。
- いずれも、本文を引数に入れない形にする。

初回は、あるコマンドを「`.exe` で配られるはず」と思い込んで対象から外したが、npm で入れていれば `.cmd` 経由になるので誤りだった。

## 再発防止

- 全コマンドを列挙する契約テストで、実際の引数に本文が入っていないこと、12,000 字を超える文章が標準入力かファイルで届くことを固定する。
- 外部コマンドへの長文は、引数でなく標準入力かファイルで渡す。1 つで見つけた対策は、全コマンドに広げる。
- Windows 実機での再確認は、まだ。Mac の実際のコマンドで再現して直した。
