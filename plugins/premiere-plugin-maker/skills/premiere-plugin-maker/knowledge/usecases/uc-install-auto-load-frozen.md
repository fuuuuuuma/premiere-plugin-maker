## 症状

署名していないパネルは、利用者が UDT で手動の読み込みをする必要があり、受け取る側も開発者モードで使うことになる。これを避けるため、UDT なしでパネルを自動で読み込む試作を作ったが、動いたことを実機で確かめられていなかった。

## 原因

見送った理由は次のとおり。

- 試作のコミットが「作業中（wip）」で、実機未検証だった。
- 置き場所が配布物の外にあった。
- 回帰テストも、呼び出す経路も無かった。
- 必要な依存（WebSocket のライブラリ）が、インストールする一覧に入っていなかった。
- 非公式のプロトコルに頼っていた。
- 確認なしにパスから読み込む動きだった。

## 直し方

コードは変えずに凍結し、ブランチと作業ツリーは残した。復活させるには、実機での検証、置き場所の是正、回帰テスト、依存の追加、呼び出す経路、手動の UDT へのフォールバックが要る。次に担当する人は、「サーバーを先に起動すると接続が来るか」の検証から始める。

## 再発防止

- 実機で検証していない導入の自動化は、本線に入れない。
- 残りの作業とリスクを文書にして凍結する。
- 非公式のプロトコルに頼る部分は、いつ壊れるか分からないものとして扱う。
