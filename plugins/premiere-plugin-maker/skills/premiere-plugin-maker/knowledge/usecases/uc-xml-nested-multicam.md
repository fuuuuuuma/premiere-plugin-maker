## 症状

ネスト（シーケンスの中にシーケンスを置く）や、マルチカム（複数カメラの切り替え）を使ったタイムラインで、無音カットが実体に届かない。後半ほどずれる。映像のトラックが空になる。すべてのクリップが飛ばされた場合は、「無音 0 件」と、しきい値を調整すれば直るかのような表示が出るだけで、真因が伝わらない。

## 原因

XML を実際に書き出して調べた結果、次の 3 つが分かった。

1. ネストされた `<sequence>` の完全な定義（`<media>` つき）は、文書中に 1 回しか無い。ほかは中身の無い `<sequence id="..."/>` の参照だけ。完全な定義は動画側のクリップにだけ付き、音声側は空の参照のみ。以前は `<file>` の無いクリップは警告を出して飛ばしていた。
2. 時間は秒で換算する必要がある。外側のシーケンスが `timebase 59`、内側が `4`、内側の素材の `<file>` が `29` と、三重にばらばら。
3. マルチカムの映像クリップは、XML に書き出されない。Premiere は「トラックアイテムがスキップされました」と報告する。音声側の `<link mediatype=video>` だけが残り、参照先の `<clipitem>` は存在しない。

## 直し方

1. id から完全な定義への索引を作り、ネストの内側の `<file>` まで再帰して、実体の音声に届く。
2. マルチカムは、音声クリップの `start`・`end`・`in`・`out`・`rate` と、参照先のネスト定義を写して、映像クリップを作り直す。
3. 切り方の既定は、「すべてのカメラが同時に無音の区間だけ切る」。
4. 設計としては、飛ばした理由を分類して件数を出し、「ネストのため」「マルチカムのため」と真因を伝える（設計段階。実装は未完了だった）。

## 再発防止

- ネスト版とフラット版で、カット境界が一致するか比べる。実測では、103 クリップで全一致し、同時に収録した 2 台のカメラの無音境界にも進行性のずれは無かった。
- 「何も処理しなかった」結果を、調整パラメータの話に見せない。
