## 症状

- 導入の途中で外部の AI の CLI（コマンド行の道具。codex や claude など）が応答せず、インストーラ全体が止まる。応答しないだけなのに「未ログイン」と決めつけてしまう。
- CLI を入れただけで、ログインも API キーの設定も済んでいない人が、繰り返し「改行エンジンが使えませんでした」で詰まる。
- 数分かかる文字起こしのあとの最終段階で、AI が使えないことが分かって止まる。
- 配布先では、AI の CLI にプラグインの連携（MCP の登録）が入っておらず、AI タブがシーケンスを読めない。開発機では手で登録済みだった。

## 原因

- ログインは利用者の個人アカウントに結びつく。ブラウザでの認証や、10GB 超のローカルモデルの初回ダウンロードは、導入側が代わりにはできない。
- 認証の確認に上限時間が無く、無応答が全体を巻き込んだ。
- 導入後に「実際に使えるか」を確かめておらず、手動の案内任せだった。
- 連携の登録が開発機の手作業に頼っていた。

## 直し方

1. 導入中の認証の確認には上限時間（Mac で 18 秒）を付ける。超えても本体の導入は完了させ、子プロセスを残さない。
2. 導入後に、本番と同じ形の軽い実応答で使えるかを見届ける。未ログインなら、ログインのコマンドを起動して確認し直す（回数を決めたループにする）。非対話の実行ではこの見届けを飛ばす。
3. 数分かかる処理の前に、出力先・ffmpeg・同梱スクリプト・転写の実行環境・AI の CLI を順に検査し、だめなら処理を始めず、症状・理由・次の一手を添えて即座に失敗させる。
4. 連携の登録は導入処理に入れ、何度実行しても同じ結果になるようにする（例: `claude mcp add premiere --scope user`）。
5. ブラウザ認証と巨大モデルの取得は自動化せず、README に手順を書く。

## 再発防止

- 検査に失敗したら処理を開始しないことを、テストで固定する。
- 実行前に、ローカルで動かすモデルの実ファイルがあるかを調べ、モデルを配るサイトの部品を読み込む前にオフラインを固定する。

## 出どころ

- Cut & SRT の導入設計書と引き継ぎ記録（2026-07-14〜07-21、v0.10.3）。実機の codex / claude で成功の経路だけ確かめた。未ログインから失敗へ向かう経路は未確認。
