## 症状

設計の段階で想定された問題。AI が書体の PostScript 名を作り話す。検査に通らない出力が返る。見本の画像を渡せる CLI が限られる。

## 原因

- AI に書体名を当てさせると、実在しない名前を作る。書体が 0 件の機械では、実行しても必ず書体のエラーで落ちる。
- claude など、画像を添付する引数を持たない CLI がある。

## 直し方

1. ジョブの開始時に、機械にある書体の PostScript 名の一覧を取ってプロンプトに渡す。0 件なら生成の前に打ち切る。
2. 返ってきた JSON を検査関数（書体の実在も含む）にかけ、不合格なら、コントラスト不足などの却下理由をそのまま次のプロンプトに足して作り直させる。3 回（初回と作り直し 2 回）で通らなければ、最後の理由を利用者に見せる。
3. 生成は時間がかかるので、ジョブ方式（202 と jobId を返し、結果を取りにいく）にする。
4. 見本画像つきは `codex exec -i <ファイル>` に固定し、codex が無ければ起動の前に断る。

## 再発防止

- 偽の生成関数で、合格・2 回目に合格・3 回不合格で停止・書体 0 件の打ち切りを検査する。画像の引数 `-i` が出力の引数より前に入る順序もテストで固定する。
- 実際の AI での確認は数回の手動にとどめ、課金が際限なく発生する自動テストにしない。

## 出どころ

- Cut & SRT の v0.11.0 の設計書（2026-09-23）。codex が画像を添付できる点だけ実機で確かめた。生成の品質と全体の動きは未確認。`-i` を前に置く理由は資料に記述が無い。
