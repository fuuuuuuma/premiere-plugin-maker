## 症状

新しい命令（ここでは「切る」を意味する `razor`）を、古い補助プログラムに送ると、切る代わりに再生が始まり、結果も返ってこない。

## 原因

古い補助（CEP 側の `main.js`）は、知らない命令を受けると「再生」として実行する作りだった。補助プログラムの更新は、Premiere を再起動するまで届かない。そのため、「新しいサーバー・新しいパネル・古い補助」という組み合わせが、更新の直後に必ず起きる。

実害が出たというより、更新時に起きうる問題として記録されたもの。再起動前の古い補助は「能力の一覧が空」として扱われ、再起動後に `razor` を名乗ることは確認したが、取り違えの挙動そのものを再現した記録は無い。

## 直し方

1. 補助が、状態確認（probe）の時に `features: ["razor"]` のように、できることを名乗る。
2. サーバーがそれを中継して返し、パネルは名乗った補助にだけ命令を送る。
3. 名乗らない補助には、理由（Premiere の再起動が要る）を画面に出し、代わりにマーカーを置くなど、安全な動きにする。

## 再発防止

- 新しい命令は、能力の申告（features）と必ず対で出荷する。
- 中継の部分に、名乗りの有無で送り分けるテストを置く。
- 未知の命令は「何もせず、未対応と返す」を既定にする。
