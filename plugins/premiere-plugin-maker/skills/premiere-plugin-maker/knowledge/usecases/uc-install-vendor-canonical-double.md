## 症状

- 本家側に直しが入っておらず、同じ不具合が戻ってくる。
- 古い本家のコピーを「本家」として採用してしまい、必要な関数が無くて `AttributeError` で品質確認が失敗する。
- 同期用のスクリプトが、新旧を見ずに全ファイルを上書きコピーし、同梱側にだけある改善を黙って巻き戻す恐れがあった（実際に巻き戻った事故は起きていない）。

## 原因

- プラグインに同梱している部品（vendor）と、別の場所で育てている本家（canonical）の両方に、同じ名前のスクリプトがある。どちらが新しいかを「ある」「ない」だけで判断していた。
- 「本家はいつも新しい」という前提が崩れた。同梱側が先に直され、本家より先行する期間があった。
- 実測すると、本家の側が「最新」と判定されることがなく、実行時はいつも同梱側が使われていた。途中の記録には「本家を参照している」と書かれていて、実測と食い違っていた。

## 直し方

1. 同じ直しを、同梱と本家の両方に入れる。
2. 本家を採用する前に、ファイルの中身に目印の文字列（例: 新しい版にしか無い定数名）があるかを調べる。無ければ同梱側に切り替える。
3. 同期スクリプトは、引数なしなら「差分があれば差分を見せて止まる」にする。上書きは「指定したファイルだけ」「全部（危険）」と、わざと選ばせる。
4. 同梱側にだけある改善は、本家に移す（先行した直しを本家へ持っていく）。
5. 意図的に食い違わせる箇所（例: Windows のドライブ文字を直す処理）は、スクリプトの冒頭に書いて台帳にする。

## 再発防止

- 同梱が欠けていないかのテストと、偽のホームフォルダでの通し試験を置く。
- 動作中のサーバーが、どちらの部品を使っているかを状態確認の応答に出す。
- 二重に持つコードは「直したら両方」を手順にして、動いている側を確かめる。

## 出どころ

- Cut & SRT の失敗記録と引き継ぎ記録（2026-07-16〜09-24、6 回ほど再発）
- 作者の開発メモ（同梱コピーと本家の取り違え）
