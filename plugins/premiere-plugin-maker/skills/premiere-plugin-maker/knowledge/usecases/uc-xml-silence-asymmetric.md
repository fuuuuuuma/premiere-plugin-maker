## 症状

無音カットの結果で、前は詰まっているのに、後ろに余韻が残りすぎる。全カットで一定して起きる。

## 原因

余白（パディング）の計算は、最初から前後が完全に対称だった（無音の始まりに +2、終わりに -2 フレーム）。コードの変更で後退したわけではなく、fps を変えても両端に同じ係数を掛けるだけで、非対称は生まれない（計算で確かめた）。

非対称の唯一の源は、`ffmpeg` の `silencedetect` の端の振る舞いだった。発話の「頭」は鋭く立ち上がるので、誤差 0 フレームで正確に捉える。いっぽう発話の「終わり」は、音が緩やかに減衰するため、RMS（音の大きさ）の判定が約 1 フレーム遅れて落ちる。音声を時間反転して逆向きに検出しても、改善は 0.3 フレーム止まりで、後ろの余りが 3.0 フレーム、前が 2.0 フレームのまま残った。

## 直し方

1. `silencedetect` をやめ、自作の検出（`detect_silence_envelope()`）に替える。
2. 20ms の中央窓の RMS を、1 本のエンベロープ（音量の輪郭）として求め、−45dB を横切る点で、前後を同じ基準で定義する。そうすれば、対称な余白が、定義のうえでぴったり前後同じ長さを残す。
3. 実装は、ffmpeg で生の PCM（`-f s16le -ac 1 -ar 16000`）をパイプで受け取り、numpy で累積和を使って O(N) で中央窓の RMS を求め、静かな連続区間のうち最小無音長以上のものを取り出す。

## 再発防止

- 補正値（後ろだけ詰める trail-bias）で非対称を埋めるのは対症療法で、過補正になる。
- 端の精度の問題は、まず「検出器が前後で同じ基準か」を疑う。
- 閾値や窓を変えるときは、独立した別の基準（別の窓の RMS）で、前後の差を実測してから決める。実測では、後ろの余り 1.95 フレーム、前 1.93 フレームで差 0.02 フレームと、実質対称になった。64 分の素材も最後まで通った。
