## 症状

- 短い確認は通るのに、本番だけ失敗する。
- 改行の不一致が「応答確認に失敗」と表示された。単一のエンジンの失敗が「全エンジンで失敗」と表示された。いずれも認証の問題だと誤認させた。

## 原因

- 確認の文は改行が無く、Windows の cmd.exe を素通りした。本番は 15KB 超で、渡し方（引数か標準入力か）が違った。
- エラー文言が、失敗の種類とずれていた。

## 直し方

1. 確認も標準入力の経路に統一する（claude なら `[実行ファイル, "-p"]` に本文を標準入力で渡す）。
2. 文言を「改行処理に失敗しました」へ直す。確認の失敗と実行中の失敗は、表示する関数も分ける。

## 再発防止

- 確認の経路が本番と一致することを検査するテスト。
- 確認の入力は、本番と同じ長さ・同じ改行の種類にする。

## 出どころ
