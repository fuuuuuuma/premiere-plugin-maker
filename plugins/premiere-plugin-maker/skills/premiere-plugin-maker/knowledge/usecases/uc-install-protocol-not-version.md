## 症状

パネルかサーバーの片方だけを更新すると、通信の約束が合わずに動かない。別の小さな常駐ブリッジでは、新しい経路（`/vision`）を足したのに版数を据え置いたため、古いブリッジにパネルが警告を出さず、404 で失敗した。

## 原因

画面の「ブリッジが古い」という警告が、版数の文字列が一致しているかだけを見ていた。常駐プロセスのある配布物では、画面とプロセスが別々に更新されるので、版が必ずずれる。版数の違いは、「通信の約束が違う」とは限らない。

## 直し方

1. サーバーが通信の約束の番号（`bridgeProtocol`）を持つ。パネルはそれを照合し、不一致なら接続せず更新を促す。
2. もう一つの方法として、サーバーの `GET /status` が「できること」の一覧（`capabilities`）を返し、パネルが足りないものを照合する。足りなければ 404 を「ブリッジが古い」というエラーに読み替える。
3. 更新手順は「サーバーの ZIP → パネルの .ccx → 再起動 → 版の確認」の順に固定する。
4. 自動起動の設定済みの利用者には、入れ直しても古い版が動き続けることがある、と案内する。

## 再発防止

- 新しい経路や命令は、通信の番号か能力の申告と対で出荷する。
- 別配布の画面と常駐プロセスは、版数の比較で互換を判定しない。

## 出どころ

- Cut & SRT（通信番号 2）と別の小さなブリッジの実装（2026-07-31、2026-10、実機で確認）
