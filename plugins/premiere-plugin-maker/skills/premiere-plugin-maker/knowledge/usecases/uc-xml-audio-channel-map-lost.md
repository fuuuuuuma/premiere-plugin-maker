## 症状

ピンマイク 2 本を別々のチャンネルに録った素材を、複数トラックで無音カットすると、音声チャンネルのプリセットが「ファイル」から「カスタム」に変わり、チャンネルのつながりが崩れる。

## 原因

Premiere の FCP XML の書き出しは、既定の割り当て（トラック N ← ソース N）しか記録しない。実際の XML の音声クリップ 2724 件を比べると、`<sourcetrack><trackindex>` が入力と出力で一致していた。プラグインを使わなくても、書き出して読み直すだけで再現する。つまり、プラグインのコードの誤りではなく、XML という形式の限界だった。

## 直し方

1. UXP には、クリップを分ける API もチャンネル割り当ての API も無く、プラグイン側での修正は断念した。
2. 音声トラックが 2 本以上あるとき（`seq.getAudioTrackCount()`）は、処理ログと結果のカードに警告を出す。
3. 利用者向けの導入ガイドに、再現の手順と復旧の方法（クリップを変更 > オーディオチャンネル）を載せる。

## 再発防止

- 不具合の原因を自分のコードだと決めつける前に、プラグインを介さない「書き出し → 読み直し」で再現するかを確かめる。
- 警告を作る処理を、テストで固定する（4 件）。
- 記録の食い違い: カットの前の XML がすでに `sourcetrack=2,2,1,1` で、「既定の割り当てのみが記録される」説と合うかは確かめていない。のちに、CEP の QE razor でクリップを分けることで、分割 API が無い問題を回避した版が出た。

## 出典

- Cut & SRT の作業記録と導入ガイド（2026-07-27、v0.9.13〜v0.9.15）
- 実際の XML の対 2724 クリップを全件比べた（機械検証）。警告表示の実機確認は無い
