## 症状

コードを直しても、動いているサーバーやパネルの挙動が変わらない。たとえば次のような状態だった。

- 動いているコピーが、数版前の古いままだった。
- 動いているコピーの中身が、まだ統合していない別ブランチのものだった。
- パネルの表示は古い版数のままで、中身だけ新しい版相当に手で差し替えられていた。

## 原因

実際に動いているものは、バージョン管理の外にある導入先のコピーと、開発用ツールが読み込んだパネルで、作業用のリポジトリ・作業ツリー・配布 ZIP とは別物である。ブランチの切り替えや手での差し替えで、本線とずれていく。テストが全部通っても、動いている物の保証にはならない。

ZIP から展開したファイルは更新日時が固定値（1980 年 1 月 1 日）になっている。サイズと更新日時で比べる `rsync -av` は、変更を取りこぼす。

## 直し方

1. 着手前に、動いているものを特定する。プロセス一覧（`ps aux | grep <サーバー名>`）、認証付きの状態確認（`/ping`）、開発用ツールの読み込み設定ファイルで、パスと版を見る。
2. 導入先を退避（`cp -a`）してから、展開物の `__pycache__` と一時的な認証ファイルを除いて、`rsync -avc`（`-c` がチェックサム比較）で同期する。認証ファイル（`server/ready` など）は消さずに残す。
3. 常駐を再起動し、状態確認の `version` と `problems: []` で届いたことを確かめる。
4. 手で差し替えたパネルは、パッケージ（.ccx）を入れ直す。

## 再発防止

- 同期は `-c` 必須を運用ルールにする。
- 導入先の全ファイルを作業ブランチと `cmp` で比べ、応答の版数とパネルの版表示を照らし合わせる。
- 「直したのに変わらない」の第一容疑は「編集先と動いている実体が違う」と覚えておく。
- 未コミットの検証物は、正式な導入物を作れない。この場合は、動いている側が HEAD と同一かを `cmp` で確かめ、変更したファイルだけを写す。
