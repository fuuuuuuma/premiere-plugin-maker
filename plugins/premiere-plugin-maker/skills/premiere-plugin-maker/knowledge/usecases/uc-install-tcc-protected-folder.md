## 症状

利用者が書類フォルダなどに展開してインストールすると、導入が終わらない。サーバーのログに `[Errno 1] Operation not permitted` が出続ける。作者の開発機では再現しない。

## 原因

macOS の TCC（プライバシー保護）は、書類・デスクトップ・ダウンロードへの読み書きを、アプリごとの許可制にしている。許可の画面を出せない常駐プロセス（launchd が起動するもの）は、許可を求められずに拒否される。許可は実行ファイル単位なので、ターミナルから動かすと通るのに、新しく作った仮想環境の `python3` は起動直後に落ちる。

原因はまだ状況証拠だけで、利用者の実機での再確認はしていない。

## 直し方

1. インストーラが、仮想環境を作る前に置き場所を調べ、保護フォルダなら終了コード 1 で止める。
2. 止めたときは、ムービーフォルダなどの保護されていない場所へ移すよう案内する。
3. 診断コマンドも、この原因を名前で挙げて知らせる。

## 再発防止

- 置き場所の判定は小さな関数に切り出し、単体テストと、擬似的な環境での「止まる・通る」の確認を置く。
- 開発機で再現しない問題は、エラー番号（errno）と環境の違いから確度を見積もり、確度の低さを記録に残す。
