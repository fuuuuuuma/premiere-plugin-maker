## 症状

スライドインの行き過ぎ（オーバーシュート）を 5% で設計したのに、実測は約 9%（0.525 で止まるはずが 0.578 まで出た）。キーが 2 本だけのトラックで、終わりに「減速」を付けようとしても効かず、着地の減速が出ない。ExtendScript の `addKey` や `setInterpolationTypeAtKey` は戻り値が null で、補間が効いたかを読めない。

## 原因

- 区間の形は「始まりのキーの補間」だけで決まる。終わりのキーの種類は関係しない。
- 補間の種類は、直線（0）、hold（4、次のキーまで一定）、ベジェ（5、3 次ベジェ）。
- 位置 [x, y] は、道筋も曲がる「空間ベジェ」で、途中のキーの接線は（次 − 前）÷ 6、端は隣へ 1/6 になる。
- イーズイン・イーズアウト・自動は、全部このベジェになるので、設計した値の約 2 倍行き過ぎる。

## 直し方

1. 打ったキーを `getValueAtTime` で読み、式に当てはめて確かめる（数値の項目は 0.0005 以内で一致した）。
2. 設計値を半分にした（スライドの行き過ぎ 5% → 2.5%、落ちて弾む 5% → 3%）。
3. 減速は、終わりのキーでなく、途中に中間のキーを 2 本置いて作る。残像や衝撃のような動きは、始点をベジェにして加速させる。

詳しい式は ref-keyframe-interpolation にある。

## 再発防止

- 書き出した動画を 1/8 秒ごとに抜いて確かめる。
- 行き過ぎの幅は、先に決めず、実測してから決める。
- 戻り値で確かめられない API は、結果の値を読んで測る。

## 出どころ

- Effect & Design の実機の記録（Premiere 26.5、2026-09-18〜09-21）
- 位置のベジェ区間には、道筋に沿った進み方に最大 0.005 ほどのずれが残る（原因は未特定）
