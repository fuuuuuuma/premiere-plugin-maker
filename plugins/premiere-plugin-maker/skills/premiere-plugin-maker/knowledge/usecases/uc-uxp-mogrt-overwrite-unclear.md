## 症状

次のどれかが起きた。

- 「元のクリップを残す」つもりで新しい MOGRT（動くテロップ）を同じトラックに入れたら、元のクリップが上書きされて壊れた。端に 1 フレームの残骸が出た。
- 1 つ上のトラックに入れる修正をしても、元のテロップが最上段（V2）にある実際のシーケンスでは、新しいクリップが V3 でなく V2 に入った。
- 生成の長さが 5 秒の図形を、5 秒以内に 2 個置くと、1 個目が消えた。
- 置いたクリップの名前が、MOGRT の中身の名前を変えても「グラフィック」のままだった。
- ExtendScript の `importMGT(path, 開始, 2, 0)` を V2 の選択時に呼ぶと、V3 に入った。

## 原因

- `importMGT` と `insertMogrtFromPath` は、同じトラックの重なる区間を、警告なしに上書きするのが既定の動き。
- 指定したトラックが無い（上に空きが無い）と、トラックを作らず、一番上の既存のトラックに丸めて入れる。最初に試したシーケンスは V3 が空のトラックとして既にあり、この場合を踏んでいなかった。
- `importMGT` のトラック番号の引数は 0 始まり。1 始まりの番号がそのまま「1 つ上」になる。
- クリップの表示名は、MOGRT 内部の名前の欄とは別のもの。

## 直し方

1. 元のクリップは消さず、無効にして残す（`disabled = true`）。
2. 新しいクリップは、1 つ上のトラックに入れる。上のトラックが無ければ、QE の `addTracks` で先に 1 本足す。足せなければ、何も変えずに失敗として止める。
3. 上の同じ時間に別のクリップがあれば、理由を出して止める。
4. 図形の生成の長さをサーバーから受け取り、挿入の前に重なりを調べて、場所を伝えて中止する。
5. 挿入のあと、入ったトラックを確かめ、予定と違えば失敗として扱い、Cmd/Ctrl+Z を案内する。
6. 戻りの TrackItem の終わりは `ti.end = Time` で伸ばせる。名前は置いたあとに `ti.name = 本文` で付け直す。

## 再発防止

- 足した試験は、直す前のコードで落ちることを確かめてから通す。
- 挿入系の API は「重なりを警告せず上書きする」「トラックが足りないと最上段へ丸める」と覚え、挿入前に調べ、挿入後に検証する。
- UXP の `insertMogrtFromPath` は Action を返さず、その場で実行されるので、取り消しが割れる可能性が高い（取引の中から呼べるかは実機で確かめる）。

## 出どころ

- Effect & Design の実機の記録（Premiere 26.5、2026-09-17〜09-18）。この問題は 3 回起きた（図形の挿入・同じトラックの上書き・最上段への丸め）
- Cut & SRT の図形の挿入の記録（2026-07-25、v0.9.5〜v0.9.6）。v0.9.6 で症状が消えたのは、別の修正との合算で、単独の検証は無い
- 記録の食い違い: 重なりを上書きするかについて、実際に使うと元のクリップが残り上書きされなかったという報告もある。キットの部品は、どちらにも賭けず、挿入前に重なりを調べて止める側に合わせた
