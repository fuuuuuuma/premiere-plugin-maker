## 何をする機能か

AI のコーディング支援ツールから、「いまのシーケンスの様子を見て」「この選択を無効にして」「字幕を生成して」と頼めるようにする口です。Cut & SRT は **36 個の道具**（`premiere_` で始まる名前）を持ちます。

| 分類 | 道具の例 |
|---|---|
| 状況の確認 | 健康診断、シーケンスの概要、選択中のクリップ、ジョブの進み具合、設定の読み取り |
| 実行 | 無音カット、字幕の生成、テロップの整列、辞書の学習 |
| クリップの操作 | 選択・削除・無効化・移動・端の調整、クリップ棚、FX スロット、トランスフォームの設定 |
| 効果・演出 | 効果の追加・一覧、トランジションの追加・一覧、MOGRT の挿入（1 個／まとめて） |
| 書き出し | コマの書き出し（1 枚／最大 20 枚）、シーケンスの書き出し |
| マーカー・位置 | マーカーの追加・一覧・削除、再生ヘッドの移動、イン・アウト点、サブシーケンスの作成 |
| 記録・通知 | 通知、学習メモの保存、プロジェクトの保存 |

## 作り方

構成は 2 つの経路です。

- **サーバーで済む道具**（健康診断・通知・設定・辞書・ジョブの状況など）: MCP の接続口（標準入出力で JSON-RPC を話す小さな Python プログラム）が、手元のサーバーへ HTTP で聞いて即答する。
- **Premiere の操作が要る道具**: 接続口がサーバーへ依頼を出すと、サーバーはそれを**メモリ上の待ち行列**に積み、結果が来るまで待つ。パネルは **2 秒ごとに「次の依頼は？」と取りに行き**、画面のボタンと同じ関数を呼んで実行し、結果（または失敗の理由）を返す。サーバーが結果を AI に返す。

押す側（サーバー）からパネルへは送れない（push が無い）ので、必ずパネルから取りに行く形（ポーリング）です。画面のボタンと同じ関数を呼ぶので、ロジックを二重に書かずに済みます。

その他の約束:

- 待ち行列は最大 50 件、300 秒で期限切れ、再起動で空になる。待ち時間は道具ごとに決めてある（概要は 20 秒、無音カットは 180 秒、まとめての書き出しは 120 秒など）。接続口の待ち時間はそれより 5 秒長く、タイムアウトの案内文を受け取れるようにする。
- 長い処理（字幕の生成）は「開始」だけを返し、進み具合は別の道具（ジョブの状況）で読む。
- 道具の説明文には、AI への運用の指示を入れる。例: 「実行前に件数を確認する」「元に戻す操作で戻せる」「先に一覧を呼んで実在する名前を確かめる」。
- 設定を返す道具は、鍵のような値を `<名前>Configured`（保存済みかどうか）に置き換える。値は返さない。

登録は、MCP の接続口の Python ファイルを `claude mcp add premiere --scope user -- python3 <ファイルの場所>` のように指す。

## 使った API と道具

- MCP（標準入出力、プロトコル版 2024-11-05）。道具の定義は名前・説明・入力スキーマ（JSON Schema、未定義の項目は禁止）。
- サーバー側: 待ち行列（スレッドセーフ、`threading.Event` で待機）、`/agent/panel/<名前>`・`/panel/commands/next`・`/panel/commands/<id>/result`。
- パネル側: `setInterval` で 2 秒ごとに取得、`action` の名前で分岐する関数。未知の action は「unknown action」の失敗を返す。

## つまずきと直し方

- **パネルが閉じていると何も起きない**。待ち行列はパネルが取りに来るのが前提なので、パネルを開いていないと 504「パネルが応答しません」。→ 道具の説明とエラー文で「パネルを開いておく」と案内する。
- **接続情報を探す順番を間違えると、403 が延々と続く**。リポジトリから起動した接続口と、配布物を別の場所に展開して動くサーバーは別物になりがちで、隣のフォルダに古い合言葉（token）が残っていると、全道具が恒久的に 403 になる。パネルは正常なので誰も気づかなかった（実測: 健康診断が 403 で 13,310 回、200 で 94 回）。→ 探す順は「環境変数」→「アプリのデータフォルダの `server.json`」→「隣の `ready`」。**データフォルダを先に見る**のが要点。
- **接続情報のファイルが誰でも読める状態だと採用しない**。所有者だけが読める（0600）こと、通信仕様の版が合うこと、ポートが妥当なことを確かめる。403 を受けたら一度だけ読み直して再試行する。エラー文に合言葉が混ざらないよう、最後に伏せ字にする。
- **2 秒ごとの取得で、実行中に次の取得が走る**。多重実行を止めるガードがコードに見当たらない。AI が 1 つずつ道具を呼ぶ前提なら問題になりにくい（推測）。
- **AI に任せる操作は取引 1 回で戻せるようにする**。件数の多い操作は、実行前に件数を確認させる。

## 結果と今の状態

- 36 個の道具と待ち時間は、コードから機械的に抜き出して照合済み。
- 接続の仕組み（待ち行列・403 の読み直し・合言葉の伏せ字）は自動テストで固定されている。2026-08 に実際の接続の失敗を計測して原因を特定した記録がある（上の 403 の件）。
- 個々の道具の実機確認の記録は道具ごとに濃淡があり、このキットでは道具別の合否までは確かめていない。使う前に健康診断の道具と、件数を確認する読み取りの道具から試す。
