## 何をする機能か

選んだテロップに、登場・退場・強調・繰り返しの動き（スライドイン、ポップ、ゆらゆら浮遊など）を 1 クリックで付けます。動きは「現在の位置や大きさを基準にした変化」で定義するので、画面の右上に置いたテロップは、右上のままその場で動きます。残像（モーションブラー）や、前後に付くトランジションも扱えます。

## 作り方

### 動きの定義（motion.json）

動きは 1 つの JSON で表し、データだけにします。

- `anchor`: `in`（頭から）／`out`（お尻に寄せる）／`scale`（クリップ全体に伸縮）／`loop`（一定の周期で繰り返す）。
- `tracks`: 項目ごとに、時刻（秒）・値・補間のキー列。値は現在値が基準です。位置は「現在位置からの差」（画面の幅と高さで正規化）、拡大縮小は「現在値に掛ける倍率」、回転は「差（度）」、不透明度は絶対値です。
- `effects`: 動きのために足す効果（名前は日本語と英語の両方を持つ）。固定値とキー列を持てる。
- `target: "transform"`: 位置・拡大縮小・回転を、トランスフォーム効果に打つ指定。
- `fallback`: 効果を足せなかったときの代わりの動き。

画面側の計画づくりが、定義とクリップの長さから実際のキー列を作ります。`out` は末尾に寄せ、クリップより長い動きは縮め、`loop` は周期で繰り返します（周期の途中で切ると点滅が「消えたまま」で止まるので、周期の区切りで止める）。

### 品質の門

機械で検査して、通らない動きはカタログに入れません。登場は 0.25〜0.55 秒、退場は 0.2〜0.5 秒、行き過ぎは 0.06 まで、揺れは位置 0.015・回転 5 度・拡縮 0.92〜1.08 まで（これを超えると酔う）、ループの継ぎ目は元の見た目に戻ること、残像の設定が決まりどおりであること。

### 書き込みの 2 つの経路

1. **UXP の補助が書く（既定）**。パネルが計画をファイルで渡し、補助が `executeTransaction` 1 回で書く。キーだけの動きなら取り消しは 1 回、効果を新しく足す動きなら 2 回。
2. **ExtendScript が書く（補助が無いとき）**。QE で効果を足し、`addKey` で打つ。キー 1 つごとに取り消しが 1 回要るので、画面には「複数回」と表示する。

### 補間の焼き込み（bake）

UXP は、同じ取引の中で補間（イーズ）を変えられません。取引を分けると取り消しが 2 回になります。そこで、Premiere が描く曲がり方を式にして、**1 コマごとの直線キー**に展開してから 1 回で書きます。展開の規則は次のとおりです。

- 数値の直線区間は両端のキーだけ。保持（hold）は次のキーの直前のコマに同じ値を置く。ベジェと位置は 1 コマごと。
- 同じ時刻のキーは後ろの値を採る。1 つの項目のキーは 1200 個まで（繰り返しが長いときは何コマおきかに間引く）。
- 式は `ref-keyframe-interpolation`、部品は `motion-bake` にある。

### 拡大・回転の中心を文字に移す

Premiere の既定の中心（アンカー）は画面の中央です。下のほうの文字に拡大や回転を付けると、中央に向かって弧を描いて飛んでしまいます（14 種が該当）。→ 拡大か回転のキーを打つ前に、アンカーを文字の位置に移し、見た目が変わらないよう位置も補正します。傾いたテロップや、すでにキーがあるもの、文字の部品が無いもの（画像・動画）には行わず、警告で伝えます。

## 使った API と道具

- ExtendScript: クリップの `inPoint.ticks`、効果の設定項目の `setTimeVarying`・`addKey`・`setValueAtKey`、QE の `addVideoEffect`・`addTransition`。
- UXP: `createSetTimeVaryingAction(true)`、`createKeyframe` と `createAddKeyframeAction`、`createRemoveKeyframeRangeAction`、`VideoFilterFactory.createComponent`、`createInsertComponentAction`、`TransitionFactory.createVideoTransition`、`createAddVideoTransitionAction`。
- 取引の作法は `core-transactions`。時間の単位は `ref-ticktime`。

## つまずきと直し方

- **キーを打ったのに、クリップの先頭で動かない（最後の値で止まる）**。ExtendScript の `addKey` の時刻は「素材の中の時刻」で、クリップの入点が基準。この拡張が作る MOGRT の入点は約 3600 秒のため、時刻 0 に打つと入点の 1 時間前に置かれる。→ 時刻は `入点のティック + 秒 × 254016000000`。
- **日本語 UI で、残像用のトランスフォームが付かない**。QE の `getVideoEffectByName("Transform")` は、日本語 UI では名前の空の効果を返し、`addVideoEffect` が false になる。初期の診断はこの戻り値を見ずに「付いた」と誤判定していた。→ 日本語名「トランスフォーム」を先に試し、**戻り値と部品の数の増加**で確かめる。効果の内部名は `AE.ADBE Geometry`。英語など他の UI は未確認。
- **効果は付いたが残像が出ない**。シャッター角度は、トランスフォーム効果自身の動きにしか効かない。「コンポジションのシャッター角度を使用」の項目名は半角カナで、探しても見つからない。→ 位置・拡大縮小・回転をトランスフォームに打つ（`target: "transform"`）。半角名も探す。
- **「The script object is no longer valid」**。→ 取引の外で await して Action を作らない（`core-transactions`）。
- **動きの前に、時刻 0 の余分なキーが残る**。時間変化をオンにすると、再生ヘッドが 0 のときに時刻 0 にキーが 1 つ増える。→ 入点より前を範囲で消す。
- **同じ取引で足したキーを消せない／足した効果に値を入れられない**。→ 範囲削除を使う。効果を足す取引と値を書く取引を分ける。
- **トランジションの長さが 0.5 秒だと 14 コマに切り捨てられる**。→ 「コマ数 × 1 コマのティック」で渡す。
- **全部失敗したのに「動きを付けました」と出た**。結果の成否を初期値のまま返していた。→ 書くつもりのキーの数と、実際に書けた数を比べ、0 なら失敗にする。取引の戻り値も見る。1 つの項目が失敗しても残りは当て、失敗した名前と理由を必ず伝える。
- **位置の動きが、設計より約 2 倍行き過ぎる**。イーズ（easein・easeout・auto）は、すべて Premiere のベジェになり、位置は空間補間で道筋が曲がる。→ 設計の行き過ぎを半分にして出荷した（スライドは 5% から 2.5%、さらに 1.2% へ。弾む落下は 5% から 3%）。空間補間の規則は完全には分かっていない。

### 記録が食い違う所

| 話題 | 記録 A | 記録 B | キットの部品が合わせた側 |
|---|---|---|---|
| 古いイーズの番号（1〜3）が効くか | 設計時は「効くかもしれない」 | 実測では、すべてベジェ（5）になる | 実測に合わせ、イーズは使わず、焼き込みで再現する |
| 2 キーだけのトラックの終端の減速 | 終端にイーズを付ければ減速する想定 | 始まりのキーで区間の形が決まるため効かない（作者の記録のみ。コードでは裏づけ無し） | 部品は、始まりのキーの補間だけが区間の形を決めるという実測式に従う |
| ExtendScript の経路と補助の経路の見た目 | 同じ動きのはず | 16 種を比べると、14 種は差 0.04 以下。横スライドと弾む落下の 2 種は、位置が行き過ぎて戻る 1〜2 コマで 4〜6 画素ずれる | 見て分からない差なので、この精度で確定した |

## 結果と今の状態

- 取引 1 回 ＝ 取り消し 1 回を、17 種のアニメで確かめました（キーだけなら 1 回、効果を足すなら 2 回。複数のクリップに同時に当てても回数は同じ）。
- 20 秒のテロップに繰り返しの動きを当てた実測は、キー 589 個・取り消し 1 回・依頼から結果まで約 3 秒です。
- 入りの動きの後に出の動きを重ねる組み合わせでの中心の補正は、テストだけで、実機では未確認です。
- 空間補間の細かい規則、速度を変えたクリップでのキーの位置、ロックされたトラックでの失敗の出方は未確認です。
