## 何をする機能か

テロップの見た目と動きを、言葉で頼んで作るための小さなプラグインです。Premiere の中で動くパネルではなく、Claude Code や Codex に話しかけて使う「スキル」（AI への手順書）と、ファイルを生成する Python スクリプトの組み合わせです。

スキルは 4 本あります。

| スキル | 頼み方の例 | 出てくるもの |
|---|---|---|
| telop-style | 「高級感のある金の明朝で、縁は二重」 | `.prtextstyle`（テキストスタイル）と見た目の試算図 PNG |
| telop-motion | 「左からスライドインして最後に減速」「ずっと小刻みに揺れる」 | `.prfpset`（エフェクトプリセット） |
| telop-from-image | 参考画像を添えて「この雰囲気で」 | 画像を観察して書体を比べ、`.prtextstyle` を作る |
| telop-catalog | 「作ったものを一覧にして」 | 検索とフィルター付きの一覧ページ（HTML） |

Premiere の API は使いません。生成したファイルを、利用者が Premiere の読み込み機能（テキストスタイルは「プロパティ → テキストスタイル → 読み込み」、プリセットはエフェクトパネルのメニューから「プリセットを読み込み」）で取り込みます。パネルを作らなくても、テロップ作りという仕事が成り立つ例です。

## 作り方

### 全体の構成

```text
kazaru/
  .claude-plugin/          marketplace.json と plugin.json
  skills/<スキル名>/SKILL.md   4 本。必要なら references/ に対応表
  scripts/kazaru.py        入口（サブコマンドを持つ 1 本の CLI）
  scripts/kazaru_core/     中身（スタイル生成・プリセット生成・試算図・一覧・書体の列挙）
  examples/                すぐ動く定義のひな形
  tests/test_selfcheck.py  自己検査 1 本
```

CLI のサブコマンドは style・motion・preview・fontsheet・colors・stack・fonts・catalog・check・example の 10 個です。スタイルもモーションも、生成の直後に自分で検査（verify）し、「verify OK」が出なければ失敗として扱います。`check` で既存ファイルの単独検査もできます。

### スキルの型

どのスキルも「注文 → 設計表（JSON）→ 生成 → 機械検査 → 試算図を見て直す → 納品」の往復で作られています。

1. 注文の言葉を、references の対応表で数値に直す（用途や雰囲気から、書体の種類・サイズ・塗り・線・影・帯へ。動きなら基準・秒数・動かす項目・緩急へ）。この表が再現性の中心です。
2. 設計表（JSON）を作業フォルダに書く。
3. CLI で生成し、機械検査を通す。
4. スタイルは試算図 PNG を見て直す。往復は 1〜2 回で止める。
5. 場所・読み込み手順・使った書体名を短く伝える。

迷う項目は聞き返さず、基本形（白文字に黒い縁と薄い影）からの差分で決めて進める作りです。

### スクリプトの場所の探し方

スキルから Python スクリプトを呼ぶとき、置き場所が環境で変わります。Claude Code は SKILL.md の中の素の変数 `${CLAUDE_PLUGIN_ROOT}` をプラグインの場所に置き換えますが、Codex は置き換えません。そのため、このスキル群は「変数の値 → Codex の導入先 → Claude Code の導入先 → SKILL.md の 3 つ上のフォルダ」の順にファイルを探し、最初に見つかったものを使います。SKILL.md に個人のパスは書きません。

### 書体の扱い

- 書体は Adobe Fonts に限ります。有効化した書体は OS のフォント一覧には出ない隠れた場所に置かれるため、専用のサブコマンド（`fonts --adobe`）で PostScript 名（書体の内部名）を列挙してから選びます。
- 書体名を記憶から書かない、が決まりです。列挙に出ない書体は Premiere で代わりの書体に置き換わって表示されます。
- 参考画像から作るときも、書体名を当てにいきません。太さ・角・ウロコ・線の本数を言葉にして、候補を並べた比較シートで選びます。色は目分量ではなく、画像から主要色を測るサブコマンドで取ります。

### オリジナルで作る方針

他人のテンプレートや既存番組の再現を頼まれても、配色と数値は毎回自分で決めます。「〜風」は雰囲気の翻訳であって複製ではない、というのがスキルの守ることに明記されています。

## 使った API と道具

- Premiere の API は使いません。ファイル形式を直接組み立てます。
- `.prtextstyle` は Premiere のプロジェクト XML で、見た目は「ソーステキスト」というパラメータの FlatBuffer（バイナリの入れ物）に入っています。書き込みと読み込みを自前で実装し、「書いて読み戻して、もう一度書いて同じになる」往復一致をテストで確かめています（形式の詳細は `ref-prtextstyle`）。
- `.prfpset` は「トランスフォーム」エフェクトのキーフレームを持つプリセットです（詳細は `ref-prfpset`）。位置は画面に対する割合で書き、`[0.5, 0.5]` が元の位置です。
- 試算図・書体比較・色の抽出にだけ Pillow（Python の画像ライブラリ）を使います。生成そのものは標準ライブラリだけで動きます。
- 配布は Claude Code と Codex の両方から同じリポジトリで入れる形です。Codex は `.claude-plugin/marketplace.json` もそのまま読めるため、片方の定義だけで両対応になります。

## つまずきと直し方

- テキストスタイルは位置やアニメーションを持ちません。動きはプリセット側の仕事です。両方を 1 つのファイルに入れようとしないでください。
- 線の幅は輪郭の中心に乗る幅なので、外側に見えるのは半分です。黒い縁は大きい文字で 10〜14 が標準の目安です。
- 線は内側から外側の順に書きます。内側ほど細くすると見やすくなります。
- 発光（グロー）はぼかしを強くした影で作ります（距離 0、サイズとぼかしを大きく、明るい色）。
- 動きの「ずっと揺れる」はクリップの長さに比例します。長いクリップほどゆっくりになるので、納品時に一言伝えます。
- 書体を有効化していないと、見た目が試算図と変わります。納品時に「Adobe Fonts で有効化してください」と伝えます。
- 試算図はブラウザや画像ライブラリでの近似です。線の太さやぼかしは Premiere で少し変わります。動きのほうはプレビューが作れないので、Premiere で確かめます。
- 書かない値は `null` にします。空の配列より安全です。

## 結果と今の状態

- 初版（2026-09-04）で、多重線・グラデーション塗り・影・発光・帯のスタイル生成と、トランスフォーム 6 項目のモーション生成、試算図、書体比較、一覧ページが入りました。
- 開発は Mac で行われ、自己検査（同梱サンプルから生成 → 検査 → FlatBuffer の往復一致 → 一覧の件数）が通ります。README は「macOS で開発・確認」と書いていますが、生成物を Premiere の版ごとに読み込んで確かめた記録や、Windows の実機確認は資料にありません。Windows でも Python が動けば生成はでき、Adobe Fonts の置き場は `%APPDATA%` 配下を見る作りですが、確かめてはいません。そのため status は partial です。
- このキットでの使いどころ: テロップの見た目を作る機能の「ファイルを作って渡す型」の見本、およびデザインタブのような機能の素材づくり。形式の知識はスクリプトとテンプレート XML に閉じ込め、スキル側は「言葉 → 数値」の表だけを持つ、という分け方が参考になります。
