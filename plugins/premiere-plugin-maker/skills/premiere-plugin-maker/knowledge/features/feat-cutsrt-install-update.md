## 何をする機能か

Cut & SRT は 2 つのものを別々に配ります。**パネル**（Premiere の中の画面）と**サーバー**（手元で動く Python のプログラム）です。受け取る人が詰まらないよう、**導入と更新を、やり直せる（冪等な）手順**にしています。この記録は、その作りと、配布で踏んだ罠です。

## 作り方

- **配るもの**: パネルは Creative Cloud から導入する `.ccx`、サーバーは OS ごとの zip（Mac 版・Windows 版）。両方に同じ設定ファイル（`build_info.json`）を持たせ、版数と通信仕様の版を一致させる。zip にパネルのファイルは入れない。
- **版ごとの固定フォルダ**: サーバーの本体は `runtime/<版>/` に置き、「いま使う版」を `current.json` に書く。設定・辞書・一時ファイル・専用の Python 環境は別の場所に分け、**更新やアンインストールで消さない**。
- **Mac のインストーラ**: 3 段階で作る。(1) 全項目を検査、(2) 足りないものをまとめて直す、(3) 再検査して一覧を出す。「1 回実行→エラー 1 つ→直す」を繰り返すと初心者が離脱するため、最初に全部を見てまとめて直す形に変えた。検査だけの実行（`--check-only`）、同じインストーラの二重起動を防ぐ鍵、失敗したら旧版に戻す巻き戻しを持つ。専用の Python 環境へ入れる依存は、ハッシュ付きの固定一覧（lock）から `--require-hashes` で入れる。
- **Windows のインストーラ**: 中身はファイルの完全性の検査（`files.sha256`）、予約名とリンクの拒否、一時フォルダへコピーして再検査してから正式な場所へ移す、同じ版が既にあれば検証して再利用して上書きしない。常駐はタスクスケジューラ（ログオン時に起動、窓を出さない）。
- **常駐の切り替えは最後**: 全項目が OK のときだけ `current.json` を書く（切り替えの確定点）。失敗したら旧版の常駐設定に戻す。
- **接続情報**: サーバーはポートを確保できた後にだけ、`server.json`（所有者だけ読める）に、合言葉・ポート・版・通信仕様を書く。パネルは版と通信仕様が違えば接続せず「同じ版へ更新してください」と案内する。
- **版数の出どころは 1 か所**: `build_info.json`。パネル・サーバー・配布物の生成が全て同じファイルを読む。HTML に版数を直書きしない。
- **版を上げる基準**: Mac と Windows の**両方に関わる変更のときだけ**上げる。片方だけの修正は同じ版のまま作り直し、変更履歴は同じ版の行に追記する。

## 使った API と道具

- UXP Developer Tool の Package（`.ccx` の作成）、または自作で UDT と同じ形の zip を組む方法。自作の `.ccx` の Creative Cloud での導入は、実機で確かめる必要がある。
- Mac: launchd（`RunAtLoad`・異常終了時の再起動・再起動の間隔 10 秒）。Windows: タスクスケジューラ。
- 配布物の生成スクリプトと、配布物の検査（個人のパス、秘密らしい名前、実行ビット、日本語ファイル名のフラグ）。

## つまずきと直し方

- **同じ版で入れ直しても更新されない**。版ごとのフォルダは「変えない」前提で、既にあれば検証だけして上書きしない。サーバーが応答していれば再起動もしない。半日気づかなかった例がある。→ 受け取る人への手順として「先にサーバーを削除（アンインストーラ）→ Creative Cloud からパネルも削除 → 新しい配布物を入れ直す」を、ガイドと同梱の案内に明記する（設定・辞書・専用の Python 環境は消えない）。開発者は、該当の版のフォルダを退避→インストーラ→サーバーの再起動→認証つきの疎通確認の順で更新し、導入先の全ファイルを作業中のものと `cmp` で突き合わせる。Windows は、中身を手で直すとハッシュ不一致で導入が止まる。
- **名前に secret / token / credentials を含む部品が、配布から黙って落ちる**（2026-10-05）。配布の生成は、秘密情報らしいファイル名を自動で外す。鍵の置き場の部品がこの名前で、配った先のサーバーが起動時の import で止まるところだった。→ 部品名を `keychain_store` に変え、「配布物の中のサーバー部品を全部 import できる」テストを足した。新しい部品を足したら、**作った zip を展開して隔離したホームで全部 import してから配る**。
- **個人のパスが配布物に入る**: 他のプラグインから写した部品の来歴ファイルに、開発機のパスが入った。→ 写すスクリプトでホームを `~` に置換し、配布対象の全テキストを走査して ユーザー名入りのホームフォルダのパスを探すテストで止める。
- **新しいパネルのファイルを足したら、配布の一覧（3 か所）にも足す**。足し忘れは検査テストが止めた。
- **Windows 向け**: Mac 専用の場所（`/Applications`・`~/Library`）を固定で探す部品は、Windows で必ず失敗する。写した部品は同一性をハッシュで守る設計なので、OS の違いは写した部品を触らず、呼ぶ側の薄い層で吸収する。パイプの既定の文字コード（cp932）で絵文字が書けず落ちるので、UTF-8 を明示する。PowerShell のスクリプトは BOM 付き UTF-8、`.bat` は ASCII だけにする。
- **ffmpeg の導入**: Mac はインストーラが Homebrew から入れる。Windows は自動で入れないので、先に `winget` か手動で入れる（案内に明記）。
- **「ターミナルでは動くのにパネルが ffmpeg を見つけない」**: 常駐のサーバーは自分の PATH しか知らない。→ 常駐の設定に Homebrew の場所を含め、インストーラを再実行する。
- **OneDrive の同期対象に展開しない**、SmartScreen は「詳細情報→実行」と案内する。
- **Windows の自動起動（ログオン時）は未確認**。サーバーが動くところまでの報告のみ。

## 結果と今の状態

- Mac は実機で導入・更新を繰り返している。Windows は導入して動作する報告があり、自動起動は未確認。
- 配布の生成・検査の自動テストは多数あり、秘密らしい名前・個人のパス・実行ビットなどの事故をそれぞれ止める。
- 公開時は「実機で通した Mac の手順」と「報告ベースの Windows の手順」を分けて書く。
