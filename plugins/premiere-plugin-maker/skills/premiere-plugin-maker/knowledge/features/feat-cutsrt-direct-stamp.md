## 何をする機能か

演出タブの機能の 1 つです。選んだクリップの人物の顔に、驚きマークや汗のような絵（スタンプ）を貼り、**顔が動いてもスタンプがついてくる**ようにします。スタンプは同梱の 8 種に加え、利用者が自分の画像（PNG・JPEG）を足せます。

## 作り方

1. **顔を測る**: サーバーが動画を毎秒 10 コマ・幅 480 ピクセルに縮めて、顔検出モデル（YuNet。OpenCV の公開モデルで MIT ライセンス）を onnxruntime で動かす。1 コマ約 22 ミリ秒。毎コマではなく間引くのは、追従の滑らかさに十分で、長いクリップでも待たせないため。
2. **位置を合わせる**: 検出した顔の位置は元の動画の座標なので、Premiere のシーケンスの上でどこに見えるかへ変換する必要がある。クリップには「位置・拡大・回転」のモーションや、シーケンスの大きさとの食い違いがあるため、**シーケンスのコマそのものを PNG で書き出して**、その画像で顔をもう一度実測する。実測が失敗したら、クリップのモーションの設定値から計算で代用する。
3. **スタンプの画像を作る**: スタンプ単体ではなく、**シーケンスと同じ大きさの透明な画像**に、スタンプを 25% の大きさで置いた PNG を作る（サーバー側で作る）。これを取り込んで配置すると、「フレームサイズに合わせる」設定がオンでもオフでも位置がずれない。
4. **配置する**: 顔の位置の時系列を、位置のキーフレームに変換して付ける。1 つの取引で付けるので取り消しは 1 回。

## 使った API と道具

- UXP: `Exporter.exportSequenceFrame`（コマの PNG 書き出し）、素材の取り込みとトラックへの配置、位置のキー（`ref-keyframe-interpolation` の焼き込みと同じ考え方）。
- サーバー: 顔検出（YuNet の onnx と onnxruntime）、画像処理、スタンプ画像の合成。
- スタンプ 8 種は、権利の心配がないように自作のオリジナルにした。怒りマークは、十字の隙間を作り直して一般的な記号と似すぎないようにした。
- 利用者が足した画像は各パソコンのデータフォルダへ PNG に直して 1024 ピクセルに縮めてしまい、配布物には入れない。

## つまずきと直し方

- **コマの PNG が、完了の返事より後に書かれる**。`exportSequenceFrame` は書き終わる前に返るので、すぐ読むと「一時フォルダの外」「ファイルがない」の誤ったエラーになり、顔の実測が失敗した。→ サーバーが最大 15 秒、ファイルが現れてサイズが落ち着くのを待ってから読む。
- **実測が失敗した場合の代用**: 最初の実機では、この待ちの問題で実測が失敗し、モーションからの計算で位置が決まった。計算の代用があるため、機能としては成功した。
- **フレームサイズに合わせる設定の違い**で、スタンプの位置と大きさが変わる。→ 透明なシーケンス大の画像に置く方式で解消。
- **UXP では `dataset` が読めないことがある**ので、つまみなどの要素の属性は `getAttribute` で読む。
- **新しいパネルファイルを足したら、配布の一覧にも足す**。`direct_tab.js` を追加したとき、配布に入れる 3 つの一覧（パネルのルートファイル・パネルだけの一覧・配布用 zip の一覧）の全部に足す必要があった。足し忘れは検査のテストが止めた。
- この機能は外部サービスも鍵も使わず、顔検出はパソコンの中だけで済む（映像を外へ送らない）。

## 結果と今の状態

- 実機で、顔についていくスタンプが貼れるところまで確認済み（コマの書き出しを待つ直しのあと）。
- 未確認: 真上のトラックへの自動配置、取り消しの回数、実測が成功する条件での位置精度。
- Python 側の自動テスト・パネルの JS テストは全て合格している（試験の件数は版ごとに変わる）。
