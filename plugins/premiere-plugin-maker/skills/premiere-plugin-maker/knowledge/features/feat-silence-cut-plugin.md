## 何をする機能か

アクティブなシーケンスの音声から、しゃべっていない区間を見つけ、タイムラインの上で直接切り取る、初期の無音カットです。UXP のパネルが画面と Premiere の操作を、Python の小さなサーバーが無音の検出とキー操作を受け持ちました。

**後継は Cut & SRT の無音カットです（`feat-cutsrt-cut`）。** そちらは、シーケンスを XML に書き出して、切った XML を作り、読み込み直す方式で、キー送信はしません。この記録は、「先行実験としてどう作り、なぜ置き換えられたか」を残すためのものです。切り方は真似しないでください。

## 作り方

構成は、パネル（UXP）と、手元で動くサーバー（Python、標準ライブラリだけの `http.server`、`127.0.0.1` の 1 つのポート）の 2 つです。

1. パネルがシーケンスのフレームレートを調べる（`getTimebase()` から逆算。手動で上書きもできる）。
2. パネルがサーバーへ「検出だけ」を頼む。サーバーが、`ffmpeg` の `silencedetect` で音声トラックの各クリップを調べ、ソースの時刻をタイムラインのフレームに換算し、重なりを併合し、前後の余白を引いて「切る区間」にする。
3. パネルが、区間を**後ろから順に**処理する。各区間で、シーケンスにイン点とアウト点を打つ（取引）、再生ヘッドを動かす、サーバーに「リップル削除」を頼む、を繰り返す。後ろから行うのは、先に削ると、残りの区間の位置がずれるため。
4. サーバーのリップル削除は、タイムラインのタブの位置を絶対座標でクリックしてフォーカスを移し、Premiere 側で割り当てたキー（既定は F）を送る。

設定の既定値は、しきい値 −35dB、最短の無音 6 コマ、前後の余白 2 コマずつです。

動作の前提は、Premiere のキーボードショートカットで、イン・アウトのマーク、リップル削除が「アプリ全体」のスコープで割り当て済みであること、サーバーを動かす Python に macOS のアクセシビリティ権限があることでした。

## 使った API と道具

- UXP: `sequence.createSetInPointAction`／`createSetOutPointAction`（フレームの精度で動く）、`setPlayerPosition`（再生ヘッドの移動）、`getTimebase()`（1 コマの長さの TickTime）、`getInPoint()`／`getOutPoint()`（結果の確認）、`TickTime.createWithSeconds`。
- サーバー: `ffmpeg`、`silencedetect`。macOS ではクリックとキーの送信に Quartz のイベント、位置の取得に AppleScript。
- 常駐は launchd（導入用の `.command` を 1 回実行）。

## つまずきと直し方

- **UXP の API だけでは、クリップの途中を切れなかった**。検証の表では、`TrackItem` の開始・終了・入点・出点を変える Action、`TrackItemSelection` への追加、`createRemoveItemsAction` に配列を渡す方法が、いずれも失敗した。→ 最終的にキー送信（リップル削除）に倒した。後続の Cut & SRT は、この判断自体をやめて XML の往復にした（後述の食い違いも参照）。
- **キー送信は、権限・座標・割り当てに依存する**。Premiere は、パネルの階層を OS のアクセシビリティに公開しない。そのため、タイムラインのタブは絶対座標のクリックでしか触れない。→ 3 秒のカウントダウンで位置を記録する「キャリブレーション」を用意したが、ウィンドウやワークスペースが変わると外れる。操作中は、Premiere を前面に保ち、マウスやキーに触れない前提。
- **UXP の `<input>` は `text-align: center` を無視する**。フレームレートの入力欄が中央に揃わなかった。→ 親の枠で中央に置く、ステッパーにする、が試された。完全な中央は未達のまま着地した。
- **区間が多いと、クリップが断片化する**。73 区間の切り取りで、映像が 74 個に分かれた（リップル削除の仕様）。
- **フレームレートの取得**。→ `getTimebase()` の逆算は動いた。`settings.videoFrameRate` のようなプロパティは、実機に存在しない。
- **TickTime の作り方**。`createWithFrameAndFrameRate` は、版によって第 2 引数に数値と TickTime のどちらかを要求する。→ 実行時に判別する。
- **Windows 版**は、実機なしで実装された（入力は SendInput、メニュー操作は UI Automation、常駐はタスクスケジューラ）。未確認。
- **引き継ぎ文書にある「カット前に戻す（Undo）」は、コードに実装が無い**。記録とコードが食い違っていた例として残す。

### 記録が食い違う所

| 話題 | 記録 A | 記録 B | キットの部品が合わせた側 |
|---|---|---|---|
| `TrackItem` の開始・終了・入点・出点を変える Action | この小型プラグインの表は、全部失敗 | 整列のプラグインは、グラフィックに対して開始・終了の Action が実機で差 0 で通った。この無音カットの旧版は「動いた時期」もあった | 両方載せる。グラフィックの開始・終了は通る（`feat-caption-align`）。映像クリップは原因を切り分けていない。無音カットの部品 `silence-cut` は、Action を使わず XML の往復に合わせた |
| 選択オブジェクトと削除 | この小型プラグインの表は、選択への追加が「接続が失われた」で失敗、配列の削除が失敗 | Cut & SRT は、同じ道が「実機で通った」と書き、26.3 では新規作成が後から失敗するので、`getSelection()` を再利用し、削除は 4 引数と記す | `getSelection()` の再利用と 4 引数に合わせた（`core-api-patterns`）。この小型プラグインの表は転記しない |
| アクションを取引の外で作ってよいか | 作者の実測の正典は「中で作る」 | この小型プラグインは、Sequence のアクションを外で作り、await を挟まず直後の取引に足して、実機で動いた | 「中で作る」を既定にする（`core-transactions`）。違いは、await が無い・ハンドルを保存しない・Sequence 対象、という点 |
| フレームレートの取り方 | `getTimebase()`（実機で確認） | `settings.videoFrameRate`（存在しない） | 部品は `getVideoFrameRate()` を使い、取れなければ 30 を詰めない |

## 真似してはいけない点

- **認証が無い**。サーバーは、誰でも POST でき、`Access-Control-Allow-Origin: *` で、ブラウザ上の任意のページから呼べる。しかも、他のアプリへクリックやキーを送れる。→ 手元のサーバーは、127.0.0.1 限定に加え、起動ごとの合言葉を付ける（`ref-local-server`）。
- **他のアプリへ入力を送る**設計は、権限・座標・割り当てへの依存と、事故の危険が大きい。UXP や XML でできる経路を先に探す（`core-safety`）。
- **巨大な同梱物**。Windows 用の同梱が約 600MB になり、GitHub の制限に当たった。ffmpeg は GPL のビルドで、再配布の条件も付く。→ 同梱せず、利用者の環境から探す。
- **パスで見つからないメディアを、名前で探す**（Spotlight やフォルダの走査）。同じ名前の別ファイルを拾う余地がある。

## 結果と今の状態

- Mac の本番経路は、版 2.10.5（2026-05-01）で動作が確かめられました。Windows は実機で確かめていません。
- 後に、Cut & SRT が、無音カットの本体（検出のスクリプト）、整列、クリップ・エフェクトのタブ、画面の流儀、サーバー常駐の流儀を引き継ぎました。引き継がなかったのは、キーを送って切る方式と、認証の無いサーバーです。
- 無音の検出も、後に作り直されました。この版は `silencedetect` で、終わりの側に余韻が残る非対称が出たため、Cut & SRT では音量の包絡で前後を同じ基準で測る方式にしました（`feat-cutsrt-cut`）。
- 診断用と旧経路のコードが多く残っています（呼び出し元の無い関数）。
