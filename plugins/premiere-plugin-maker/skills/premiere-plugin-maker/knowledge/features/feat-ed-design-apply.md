## 何をする機能か

タイムラインで選んだテロップ（文字のクリップ）の「見た目」を、カタログのデザインに 1 クリックで替えます。本文はそのまま、フォント・塗り・縁・影などが変わります。結果は Premiere の純正のテキストなので、あとから文字を直せます。

公式 API には「見た目だけ替える」手段が無いため、**見た目を持つ MOGRT を作って、元のクリップと入れ替える**方式です。入れ替えは「同じ開始位置・同じ長さ」で行い、元は外す（または無効にして残す）ことができます。

## 作り方

流れは 4 段階です。

1. **本文を読む**。選択中のクリップの本文を、シーケンスを FCP7 XML に書き出して読み取る（文字のクリップの値を直接読むと、本文ではなく中身のバイト列が返るため。後述）。
2. **MOGRT を作る**。Python のエンジンが、Premiere に同梱の `Basic Title.mogrt` を土台（ドナー）にして、文字のスタイルと本文を差し替えた MOGRT を作る。
3. **置く**。ExtendScript の `importMGT` で、元と同じ開始位置に入れ、終了位置を元に合わせ、クリップ名を本文にする。
4. **元を外す**。削除、または無効化して 1 つ上のトラックに重ねる（「元を残す」設定）。

### MOGRT の作り方（要約）

`.mogrt` は zip で、中に `definition.json` と、言語ごとの `project*.prgraphic` があります。`.prgraphic` はさらに zip の中に gzip で固めた XML が入った二重の包みです。作る手順は次のとおりです。

1. 土台を探す（Premiere のアプリの中の `Essential Graphics/Basic Title.mogrt`。年の新しい版を選び、Beta 版は後回し）。
2. 各言語の XML で、テキスト部品の 1 番目の設定項目（ソーステキスト）を新しい FlatBuffer のバイト列に差し替え、ハッシュを計算し直す。
3. 位置、レイヤー名、グラフィック本体の名前、尺を書き換える。
4. 識別子（UUID）を振り直す。ただし、トラックグループの `<First>` は触らない。
5. `definition.json` の識別子・名前・本文・使用書体・尺を直し、各言語の「シーケンスの識別子」を新しい XML のものに合わせる。
6. 出力する前に自己検査する（XML が正しいか、参照が全部解決するか、テキスト部品が 1 個か、バイト列が復元できるか、識別子が一致するか）。失敗したら壊れた MOGRT を出さずに止める。

文字スタイルの中身（FlatBuffer）の読み書きは `ref-prtextstyle`、MOGRT の層構造は `ref-mogrt` にまとめてあります。

## 使った API と道具

- ExtendScript: `sequence.importMGT(絶対パス, 開始ティック(文字列), 映像トラックの番号(0 始まり), 音声トラックの番号)`。戻り値は挿入したクリップで、失敗は null。`item.remove(0, 0)`、`item.disabled`、クリップの `end`（`Time`）と `name`。
- QE DOM: `addTracks`（トラックを足す）、`addVideoEffect`。
- `seq.exportAsFinalCutProXML`（本文の読み取り用）。
- Python: `zipfile`、`gzip`、`xml.etree.ElementTree`。

## つまずきと直し方

実機で分かった順に書きます。どれも、初期の想定が実機で覆ったものです。

- **挿入しても、文字の無い空のグラフィックになる**。識別子の振り直しで、トラックグループの `<First>`（映像・音声ごとに決まった定数の UUID）まで変えてしまい、メディア種別の記述と食い違ったのが原因。→ 振り直す対象を `ClipID`・`ID` と `ObjectUID`・`ObjectURef` に限り、`<First>` と `<MediaType>` は触らない。テストで守る。
- **日本語など英語以外の言語で、尺の書き換えが 0 件になる**。土台の尺を表すティック値が、言語ごとに違うため（英語と日本語・中国語・韓国語・ロシア語でそれぞれ別の値）。→ 値を固定で置換せず、各ファイル自身の値を読み、それと一致する項目だけを書き換える。
- **名前で最初の `MasterClip` を掴むと、別のものを改名する**。`MasterClip` は 2 つあり（Proxy Sequence とグラフィック）、名前の順は当てにならない。→ `SubClip` から参照をたどって特定する。
- **2026 年形式の部品に丸ごと差し替えた MOGRT は、`importMGT` で「Loading … 30%」のまま戻らず、Premiere ごと固まる**（キャンセル不可、強制終了になる）。→ 土台の部品を残して、ソーステキストのバイト列だけを差し替える方式を既定にした。丸ごと差し替える経路はコードに残っているが使わない。最初の挿入試験は 1 本ずつ、診断パネルで行う。
- **「元を残す」にしたのに元が上書きされた**。`importMGT` は、**存在しない上のトラックを指定しても、トラックを作らず、一番上の既存のトラックに丸めて入れる**。結果、元のクリップを上書きした（利用者の実機で発覚）。→ 先に QE の `addTracks` でトラックを足す。足せなければ何も変えずに失敗する。挿入後に、予定のトラックに入ったかを確かめ、違えば取り消しを案内する。
- **同じトラックに入れると、端に 1 フレームの残骸が出る**。無効にした元の上に重ねたため。→ 「元を残す」は 1 つ上のトラックに入れる。塞がっていれば、何も変えずに失敗する。
- **置いたクリップの名前がいつも「グラフィック」になる**。`importMGT` は MOGRT の中の名前を使わない。→ 置いた後に `item.name` へ本文を入れる。
- **本文が読めない（変な 1 文字が返る）**。文字クリップの値を直接読むと、本文ではなく中身のバイト列の長さを示す文字になる。→ 本文は FCP7 XML の `GraphicAndType` の項目名から読む。値を読んでそのまま書き戻すと本文が壊れる。
- **XML から別のクリップの本文を取ってしまう**。初期の計画は `pproTicksIn` でクリップを見分けようとしたが、同じ土台から作った MOGRT は全部同じ値になる。→ 見分ける鍵は「トラック番号と、開始位置のフレーム番号」。フレーム番号は ExtendScript で出す（XML の timebase は実際のフレームレートと食い違うことがある）。XML は正規表現で切らず、木として読む（`<video>` が入れ子になっている）。外部の定義を含む XML は拒否する。
- **背景画像など文字でないクリップに当てると、中身が消えた**。→ 文字の部品（`AE.ADBE Text`）があるかを先に確かめ、無ければ断る。複数選択では文字だけに当て、残りは飛ばす。
- **日本語 UI の Premiere では、英語名の「Transform」で効果が付かない**（詳しくは `feat-ed-motion`）。

### 記録が食い違う所

| 話題 | 記録 A | 記録 B | キットの部品が合わせた側 |
|---|---|---|---|
| `insertMogrtFromPath`（UXP）が重なる区間を上書きするか | 別の機能で「黙って上書きする」破壊的な API という実測 | 別の機能の実機報告では、元が残ったまま足された | 部品 `mogrt-text` は、どちらにも賭けず、挿入の前に重なりを調べて止める |
| 差し替えの取り消し回数 | 設計時は「1 回にまとめたい」 | 実測は、削除・挿入・名前・尺合わせで複数回（実機で 3 回） | 実測のとおり、複数回になると表示する。MOGRT の挿入は取引に入れられない（`core-transactions` の T10） |
| 丸ごと差し替える方式 | 設計時は有望と考えた | 実機で固まった | 土台の部品を残す方式だけを教える |

## 結果と今の状態

- Mac の Premiere 26.5 で、黄文字・赤白の二重の縁・影のデザインが正しく描かれ、`importMGT` でも UXP の挿入でも入れられました。受け入れの通し確認（差し替え、元を残す、取り消し）は合格しています。
- 日本語 UI の Premiere で確かめました。英語などの UI での挙動は未確認です。
- 次は未確認です: 再生速度を変えたクリップや、ロックされたトラックでの失敗の出方。他社製の MOGRT の中の文字の差し替え。
- 土台を選ぶ処理が「並べ替えた末尾」に頼っていて、将来、土台が複数の年の版に増えると意図しない版を選びうる（年の数値で比べる直しが未実施）。
