## 何をする機能か

「この色補正」「この位置とスケール」のような効果の設定を、見本のクリップから読み取って**スロットに保存し、別のクリップに一発で適用**する機能です。Premiere の標準機能（属性のコピー）よりも、番号を付けて何種類も持ち、キーボードで呼び出せる点が違います。MCP（`premiere_effect_slot`）からも操作できます。

元は小さな単体プラグイン（`feat-effect-shortcut`）で、Cut & SRT のエフェクトタブ（FX）に取り込みました。

## 作り方

- **読み取り（キャプチャ）**: 見本クリップのコンポーネント（効果）を順に読み、`matchName`（内部名）、表示名、固定の効果かどうか、各パラメータ（番号・名前・値・型）を記録する。キーフレームがあるパラメータは、時間変化の有無を調べ、キーの時刻（クリップの始点からの相対秒）・値・補間の種類を列で記録する。
- **保存**: Premiere のオブジェクト（`PointF` など）は JSON にできないので、`[x, y]` の配列に直して素の値で保存する。適用するときに `PointF` へ戻す。
- **適用（3 段階の取引）**:
  1. 取引の前に、非同期の準備（効果のファクトリー呼び出し、対象クリップの取り直し）を済ませる。
  2. 取引 1 つ目：固定の効果（Motion・不透明度）は既存のコンポーネントのパラメータに書き込み、それ以外の効果は新しく作って追加する。
  3. 取引 2 つ目：**追加した効果を取り直して**、パラメータの値とキーを書く（足した効果は、取引が確定するまで設定項目を持たないため）。
- **キーの書き込み**: 時間変化を有効にしたうえで、位置つきでキーを追加し、補間の種類を設定する。位置の API が使えない環境は先頭の値だけに縮退して、そのことをログに出す。
- **入口**: パネルの数字キー 1〜5、メニューのコマンド 5 個、MCP のツール。

## 使った API と道具

- `VideoFilterFactory.createComponent`（効果の生成）、コンポーネント／パラメータの読み取りと `createSetValueAction`、`createSetTimeVaryingAction`、`createAddKeyframeAction`、`createSetInterpolationAtKeyframeAction`。
- 取引の作法は `core-transactions`（Action は取引の中で作る、足した効果の値は別の取引で書く、Action は 1 つずつ足して個別に例外を包む）。

## つまずきと直し方

- **足した効果にすぐ値を書こうとすると失敗する**。→ 効果を足す取引と、値・キーを書く取引を分ける（取り消しは 2 回になる）。
- **まとめて足すと、1 つが弾かれただけで全部が「Invalid parameter」で落ちる**（色補正の一部のパラメータが拒否された例）。→ Action は 1 つずつ足し、個別に try/catch で包む。
- **座標のパラメータは普通の配列では書けない**。→ `PointF` に変換して渡す。
- **キーフレームが 1 つ目の値だけになりアニメーションが消えた**。→ キーの列と補間を保存し、時間変化を有効にして打ち直す。
- **時間変化を有効にしたとき、再生ヘッドが 0 の位置に余分なキーが増える**。→ 入点より前のキーを範囲で消す。
- **効果の保存先を localStorage に置くとき、`PointF` のような特殊な型を直接書くと壊れる**。→ 素の値に畳んでから保存。
- **Premiere 本体のキー割り当てで UXP のコマンドを呼べない版がある**。→ パネル内の数字キーで代用し、修飾キーが押されているときは反応させない。

## 結果と今の状態

- 取引の 3 段階型は実機での失敗（値の書き込みが拒否された件など）を受けて作り直したもので、効果の適用が実機で動いた記録がある。
- キーフレームの保存・適用は公式リファレンスと照らして作ったが、**実機での確認は「パネルを読み込み直して、動きのあるクリップで保存→適用」が必要**と記録されている。確認の記録が見つからないため、この部分は未確認として扱う。
