## 何をする機能か

字幕やテロップ（グラフィックのクリップ）の開始と終了を、別のトラックのクリップの境目に、許容コマ数の内で自動で寄せる、小さな UXP パネルです。無音カットの後に字幕を置くと、端が映像のカット点から数コマずれます。それを手作業で直さずに済ませます。基準にするトラックは、映像でも音声でも選べます。

この記録は、小型の単体プラグインとしての作りです。のちに Cut & SRT の「整列」タブに取り込まれ、整列の考え方は `feat-cutsrt-align` にあります。

## 作り方

- 構成は最小の 5 点（`manifest.json`、`index.html`、`index.js`、`panel.css`、アイコン）。パネルのエントリポイントは 1 つだけ。
- 権限は最小です。ファイルの権限は「プラグインの領域だけ」、ネットワークなし、ショートカット用のコマンドなし。
- 画面は、基準トラック（種類と番号）、テロップのトラック番号、許容コマ数の 3 段のフォームと主ボタン。数値は、`−` と `＋` のボタンで増減するステッパーにした。結果は「そろえた・飛ばした・失敗した」の 3 つの数で出し、処理のログは折りたたみの欄に置く。
- 処理は次の順です。
  1. 基準トラックの全クリップから境目の時刻を集める。**開始側の境目と終了側の境目は別々の一覧にする**。
  2. テロップの各クリップについて、開始は開始側から、終了は終了側から、許容コマ数の内でいちばん近い点を二分探索で探す。近い境目どうしがぶつからないように調整する。
  3. 全部の変更を **1 つの取引**にまとめて適用する（取り消しは 1 回）。
  4. 適用後に、実際の位置を読み戻して、期待した位置との差をログに出す（「検証ログ」）。

## 使った API と道具

- `project.lockedAccess` と `project.executeTransaction`、`trackItem.createSetStartAction`／`createSetEndAction`。
- 境目の時刻は、境目のクリップの `getStartTime()`／`getEndTime()` が返す TickTime をそのまま使う（`ref-ticktime`）。
- トラックの取得は、トラック番号を 1 始まりから 0 始まりに直し、`getTrackItems(種類, 空を含むか)` の引数を明示して呼ぶ。

## つまずきと直し方

1 日（版 1.0.0〜1.0.6）の試行錯誤で、次のことが分かりました。実機で確かめた記録があるのは、整列の処理（版 1.0.4 以降）です。

- **グラフィックのクリップに入点・出点を設定すると、カット点を 3 コマ飛び越えて反対側に着地した**。グラフィックの入点は 0 付近の小さな値しか持たないため、早い方向にずらすと負の時刻ができ、開始・終了の動きと入点・出点の動きが二重に効いた。→ グラフィックには `createSetStartAction`／`createSetEndAction` だけを呼び、入点・出点には触れない。実機の 7 件・許容 10 コマで、差が 0 になった。
- **開始の境目と終了の境目を 1 本にまとめると、テロップが 2 コマ後ろにずれた**。無音カットで作った映像は、隣のクリップとの間に 2 コマの余白が入ることがある。終了が次のクリップの開始に吸い寄せられた。→ 開始用と終了用の一覧を分ける。
- **TickTime の引き算で負の結果が異常な値になる／比率から作り直すと数百ティックの誤差が出る**。→ 必ず「大きい方 − 小さい方」にする。境目のクリップが返した TickTime のオブジェクトを再利用する。
- **純関数を別の JS ファイルに切り出すと、実機で完全に動かなくなった**（Node のテストは全部合格）。UXP の `require` は相対パスを解決できず、`<script src>` の読み込み順も不安定。→ 1 つの `index.js` に埋め込む。
- **初期化の途中で例外が 1 つ出ると、ボタンもログの開閉も全部効かなくなる**。→ 初期化の全体を try/catch で包み、失敗は画面のログ欄に書く。
- **`<details>` が不安定**。→ クラスの付け外しによる自前の折りたたみにする。
- **`overflow:hidden` のカードが、flex の縦並びで潰れる**。→ 直下の子要素の縮小を禁止する（`flex-shrink: 0`）。
- **3 つのフィールドを横に並べると、狭いパネルで潰れる**。→ 縦の 3 段に変更した。
- **フレームレートの取得**。初期のコードは `settings.videoFrameRate` のようなプロパティを読んでいたが、実機には存在せず、黙って 30fps に落ちる。→ メソッドで取る。非 30fps のシーケンスでは、許容コマ数のティック換算が狂う可能性が高い（推測）。雛形には持ち込まない。

### 記録が食い違う所

| 話題 | 記録 A | 記録 B | キットの部品が合わせた側 |
|---|---|---|---|
| トラックのクリップの開始・終了を変える Action が使えるか | 無音カットの小型プラグインの表は、`TrackItem` の開始・終了・入点・出点を変える Action が「全滅」 | このプラグインでは、グラフィックに対する開始・終了の Action が実機で差 0 で通った | 両方載せる。グラフィックの開始・終了は実機で通った。映像クリップへの設定は、失敗の原因を切り分けていない。部品 `ppro-kit` の方針は、グラフィックには開始・終了だけ（`core-api-patterns`）。映像の切り方は Action に頼らず XML の往復に合わせた |
| 無音カットのコードをそのまま写してよいか | 無音カットは入点・出点を打って動いた | グラフィックに写すと事故になる（映像は入点・出点が正の領域にあるため） | 写さない |
| フレームレートの取り方 | `settings.videoFrameRate` を読む（このプラグイン、無音カットの旧経路） | シーケンスの基準の長さ（`getTimebase()`）、またはメソッド `getVideoFrameRate()`。前者は実機で確認済み | 部品 `ppro-kit` は `getVideoFrameRate()`（26.2 以降）を使い、取れなければ 30 を詰めず「不明」を返す |

## 結果と今の状態

- 整列の処理は、Mac の Premiere で 7 件・許容 10 コマの実機検証に通りました（2026-04-29）。
- 画面の作り直し（版 1.0.6、ミント基調、縦 3 段、ステッパー）は、ブラウザでの確認までで、UXP の実機での最終確認の記録はありません。
- Windows の実機は確かめていません。
- 単体の小さな公開リポジトリになっています。Node の単体テストは、一度作りましたが、純関数の埋め込みで消えました。
- 雛形の土台に向くのは、最小の権限、`require` のガード、初期化の try/catch、検証ログの 4 点です。
