## 何をする機能か

編集中に必要になる素材（効果音、BGM、画像、動画、書体）を、パネルを離れずに探して、プロジェクトに取り込みます。

- 画像・動画: パネル内で検索し、「Cut & SRT 素材」というビンの中の「画像・動画」に取り込む。
- 効果音・BGM: パネル内では検索結果の案内までにとどめ、提供元のサイトで利用者が落としたファイルを、ダウンロードフォルダから取り込む。
- 書体: 一覧で探す。
- そのほかの素材やテンプレートの検索サイトは、Web タブ（`feat-cutsrt-web`）で開く。

## 作り方

1. 検索の窓口とカタログは、別に作った検索サイトの仕組みをパネルに写して使う。写した部品の来歴は管理用のファイルに記録する。
2. カタログは、取得のたびに全部を取り直さず、HTTP の `ETag` と `If-Modified-Since` を付けて問い合わせ、変わっていなければ（304）手元の保存を使う。保存先は UXP の `getDataFolder()` の中。
3. 取り込みは、ファイルを `project.importFiles` でビンへ入れる。ビンは `FolderItem.createBinAction` で作る。アクションはビンそのものを返さないので、作った後に名前で探し直す。
4. 画面は、他のタブと同じく空の枠にスクリプトで組み立てる。検索結果の一覧は、行が押しつぶされないよう縮小を禁止する（`core-ui-rules` を参照）。

## 使った API と道具

- `project.importFiles(パス, suppressUI, 取り込み先のビン, 連番画像として扱うか)`、`FolderItem` と `createBinAction`、ルートビンの列挙（`getRootItem`、`getItems`）。
- UXP の `storage`（`getDataFolder`）と `fetch`。ファイル名や拡張子の検査はサーバー側でも行う。
- 規約を調べる作業は、検索を作る前に必ずやる（下を参照）。

## つまずきと直し方

規約の扱いは、この機能でいちばん重要な部分です。素材サイトの規約は、機能の作り方を決めてしまいます。実装の前に各サイトの利用規約、FAQ、`robots.txt` を読み、次のように分けました。

- 音源（効果音、BGM）を持つ日本の無料素材サイトの多くは、「音源を鳴らせるアプリ」「動画に挿入できるアプリ」を再配布として禁じ、素材ファイルへの直リンクも禁じています。検索結果の巡回を `robots.txt` で拒むところもあります。そのため、パネルの中で試聴させたり、自動で取得したりしません。利用者が自分でサイトから落としたファイルを取り込む形にし、音源のメタデータの案内（送客型）にとどめました。
- クレジット表記が必須のものと不要のものがあります。取り込んだ素材の表記の要否は、利用者が提供元で確かめる必要があります（キットの作り手は、この確認を作る側の手順に入れてください）。
- 画像・動画は、提供元が API でサムネイルの URL を配っている場合に限って、パネルに表示します。日本の無料写真サイトの多くは、自動での収集と直リンクを禁じています。
- 外部サービスの API には、再利用や永続的な保存を禁じる条項があるものがあります。キャッシュは、規約が許す範囲の保存期間にとどめます。
- 利用規約は変わります。調べた日付を記録し、定期的に読み直します。

そのほかの実装上の注意:

- ビンの作成（`createBinAction`）は、このプラグインで初めて使った API で、実機での確認は残っています。失敗しても取り込み自体は進める作りです。
- 音声を鳴らす、タイムラインを再生する API は UXP に無い。再生は CEP 補助（`cep-helper`）の仕事で、素材の試聴は規約の面からも行わない。
- 画像や動画を置く先は、アクティブなシーケンスの再生ヘッド位置（既定は V2）です。

## 結果と今の状態

画像・動画の検索と取り込みは、Mac で作者が確かめています。効果音・BGM の手動取り込みも同様です。ビンの作成、Windows での取り込み、規約の定期的な再確認は、確認が残っています。
