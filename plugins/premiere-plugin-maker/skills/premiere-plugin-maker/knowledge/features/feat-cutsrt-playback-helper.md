## 何をする機能か

Premiere の UXP（今の拡張方式）には、**タイムラインの再生・停止**も**クリップの分割**もありません（公開されているのは再生ヘッドの位置の読み書きだけ）。これらは古い拡張方式（CEP）の ExtendScript が持つ非公式の QE DOM にしかありません。そこで、Cut & SRT は**画面を持たない小さな CEP 拡張**を一緒に入れ、再生・停止・分割（razor）だけを任せます。パネルから「再生」を押す、ピンマイクの切り替えで分割する、といった場面で使われます。

## 作り方

```
UXP パネル ──POST /playback {action}──► サーバー（最新の 1 件だけ預かる）
                                          ▲ GET /playback/next（0.4 秒ごと）
                                       CEP 拡張 ──evalScript──► ExtendScript（QE DOM で再生／停止／分割）
                                          └─ POST /playback/result（結果）
```

- **拡張は 2 つ宣言**する。画面なしで自動起動する方（1×1 の大きさ）と、画面ありの保険（メニューから手で開く）。どちらが動いても、サーバーが 1 件ずつ渡すので二重に再生しない。
- **最新の 1 件だけ保持**する。押し損ねた再生を後から溜めて流すと、意図しない再生が突然始まるため。分割は 1 回に 200 か所まで。結果は指示の番号ごとに 16 件まで覚える。拡張が 5 秒以内に取りに来ていれば「つながっている」と見なす。
- **ExtendScript のコードは、呼ぶたびにファイルから読んで一緒に送る**。manifest の指定だけに頼ると、起動時の版が固定され、直しても開き直すまで反映されない。
- **能力を名乗らせる**: 起動時に自分で試して、できる命令の一覧（例: `razor`）を名乗る。サーバーは拡張ごとに覚え、パネルの問い合わせに「分割ができる拡張はどれか」を返す。パネルは、名乗った拡張がある場合だけ分割を頼む。
- **パネルの側**: 再生・停止は、指示を出したあと 200 ミリ秒間隔で最大 12 回、結果か「拡張が受け取った」ことを確かめる。再生・停止は ExtendScript が値を返さないので、「受け取った」が成功の証になる。

## 使った API と道具

- CEP（`CSInterface.evalScript`）、ExtendScript の QE DOM: `app.enableQE()` → `qe.project.getActiveSequence()` → `seq.player.play(rate)` ほか。版で呼び方が違うので、候補を順に試し、成功した呼び方を結果に含める。
- 分割は `track.razor(タイムコード)`。タイムコードは公開 API の `Time` で作る（`time.seconds` に入れて `getFormatted(fps, 表示形式)`）。
- 導入は、拡張のフォルダをユーザーの CEP の拡張フォルダへ写し、署名なしの拡張を読ませるために `PlayerDebugMode` を有効にする。この設定は利用者に説明して許可を得てから行う。Premiere の再起動後に有効になる。

## つまずきと直し方

- **ExtendScript（ES3）には `JSON` が無い**。`JSON.stringify` を呼ぶと「EvalScript error.」としか返らず、再生ボタンが無反応になった真因だった（2026-08-16）。→ 必要な形だけ自前で文字列にする。
- **画面を持たない拡張は、HTTP の取得はできるのに `evalScript` の結果が返らない環境がある**。そこが先に指示を取ると握りつぶされて「押しても無反応」になる。→ 取りに行く前に自分で実行できるかを確かめ、5 秒返らなければ「この拡張では再生できない」と報告して取りに行かない。
- **古いヘルパーが、知らない命令を「再生」として実行する**。更新しても、Premiere を再起動するまで古い拡張が動き続ける。→ 新しい命令（分割）は、拡張が名乗ったときだけ送る。名乗らなければ理由（Premiere の再起動が要る）を出し、代わりの動き（マーカーなど）にする。
- **分割の位置が 1 フレームずれる**。タイムコードに直すときに切り捨てが入る。→ 1/4 フレーム内側を渡す。
- **Windows には導入していない**ので、分割ができない。マーカーでの縮退運用にする。
- **期限がある**: CEP は Adobe が将来既定で無効にする予定の古い方式です（`ref-cep-extendscript` に最新の日付）。古い資料の「2026 年 9 月に終了」は置き換わっている。代わりの方法が UXP に出るまでの暫定の部品と考える。

## 結果と今の状態

- 再生・停止は実機で確認済み（2026-08-16）。
- 分割は**実機で未確認**: 音声のトラックだけを切れるか、リンクした映像まで切れてしまわないか、狙ったフレームに入るか。2026-10-01 の実機試験では、切る処理が実行される条件にならなかった。
- 現行の Premiere で、拡張が今も動くかは、版ごとに確かめ直す必要がある。
