## 何をする機能か

よく使う素材の組み合わせ（ロゴと効果音、枠つきの映像など）を、番号つきの「棚」に保存しておき、あとから再生ヘッドの位置へ**ワンキーで貼り付ける**機能です。複数のクリップを選んで保存すれば、トラックの並びと、クリップどうしの相対的な位置を保ったまま貼れます。クリップ単体ではなく、**付いていた効果とキーフレームも一緒に**写します。

元は小さな単体プラグイン（`feat-clip-clipboard`）で、Cut & SRT のクリップタブに取り込みました。

## 作り方

- **保存**: 選択中のクリップの、名前・開始位置（ティック）・トラック番号・種類（映像／音声）に加え、元の素材（プロジェクト内の素材 ID）と素材の中の始点・終点を記録する。効果とキーフレームはその場で読み取って記憶するが、この部分は**メモリの中だけ**に置く（ディスクには書かない）。
- **永続化**: ブラウザ相当の保存領域（`localStorage`）に、素の文字列と数値だけを書く。保存形式は版で上げ、新しい形式は新しいキーに書いて、**古い形式のキーは消さずに読み取り専用で残す**（旧版へ戻しても棚の中身が消えない）。
- **貼り付け**: 保存した `TrackItem` のハンドルは寿命が短く、再起動で失効する。貼る直前に、タイムラインからクリップを「名前＋開始位置＋トラック」で**取り直し**、再生ヘッド位置を基準に相対位置で複製する。複製は取引の中で行い、取り消しは 1 回で戻る。
- **別のシーケンスへ貼る**: 元クリップを取り直せないので、保存時に捕えておいた素材 ID と始点・終点で素材全体を挿入してから、挿入されたクリップに始点・終点を設定し、メモリに持っていた効果を別の取引で適用する。再起動後はメモリの効果が消えるため、素材と始点・終点だけが復元される（効果は付かない）。
- **棚の構造**: 数と並び順、名前の変更、グループ分けができる形（`{グループ: [棚: {名前, 自動の名前, クリップ}]}`）に作り直した。状態を書き換える処理は、現在の状態を受け取って新しい状態を返す**純関数**にして、画面や Premiere に触れない形でテストする。
- **ショートカット**: パネル内で数字キー（1〜9、0）が棚 1〜10 の貼り付け。Cmd／Ctrl／Alt を押しているときは発火しない（アプリ側のショートカットを奪わない）。メニューのコマンドとしても 10 個登録する。

## 使った API と道具

- `Sequence.getSelection`、`TrackItem` の各種プロパティ、`SequenceEditor` の挿入・複製の Action、`createSetInPointAction`／`createSetOutPointAction`。
- 取引は `lockedAccess` の中の `executeTransaction`。Action は取引の中で同期的に作る（`core-transactions`）。
- 効果の写しは `feat-cutsrt-fx-slots` と同じ仕組みを共有する。
- 時間はティック（`ref-ticktime`）。UXP の保存領域は `localStorage`。

## つまずきと直し方

- **ハンドルを保存して後で使うと失効する**。→ 保存は素の値だけ。使う直前に必ずライブのタイムラインから取り直す。
- **単純な挿入（素材をそのまま入れる Action）では、元の効果が全部消える**。→ 挿入のあとで、元クリップから読み取った効果を別の取引で適用する。
- **キーフレームが 1 つ目の値だけ保存され、アニメーションが消えた**。→ 効果の保存で、キーの列と補間の種類を持つ形に直し、適用時は時間変化を有効にして位置つきでキーを打つ。位置を指定する API が使えない環境では先頭の値だけに縮退する。
- **別のシーケンスに貼ると効果が付かない**。→ 上記のとおり、保存時に捕えてメモリに持つ。永続化できるかが不確実なオブジェクトは、最初から「メモリだけ・失われたら縮退」と決めておく。
- **保存形式を変えたら旧版で棚が消える**。→ 新しいキーに書き、旧キーは残す。
- **数字キーが他のショートカットと衝突する**。→ 修飾キーが押されているときは反応しない。
- **UXP のコマンドへの Premiere 本体のキー割り当てが効かない版がある**。→ パネル内の数字キーを代わりの入口にする。
- **UXP は Node 単体で最後まで検証できない**。→ 純関数に切り出した部分を Node のテストで固め、Premiere を触る部分は実機で確認する。

## 結果と今の状態

- 実機で、クリップ棚のデータが保存領域に保存されることは観測済み。
- 同じシーケンス内での保存・貼り付けは、実機での利用を前提に作り直した（取引内での Action 生成など）ものです。別シーケンスへの貼り付けと再起動後の復元は、計画書の段階の記録しかなく、実機では未確認。
- 棚の名前変更・グループ分けは設計と自動テストまで。
