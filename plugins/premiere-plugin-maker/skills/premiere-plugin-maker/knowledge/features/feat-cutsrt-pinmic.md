## 何をする機能か

複数人がそれぞれピンマイクを付けた収録では、音声トラック（A1、A2…）が人ごとに分かれます。この機能は、**いま話している人のマイクのクリップだけを有効にし、ほかを無効にします**。ほかのマイクが拾う回り込みや雑音が減ります。カット点は増やしません。例外は、1 つのクリップの中で話す人が入れ替わる所だけで、そこはテロップの境目で切ります。

話者タブの「マイクを切り替える」ボタンで動かします。ベータ機能の扱いです。

## 作り方

1. 話者の振り分け（声紋・分離・文脈。`feat-cutsrt-speaker`）と同じ解析を、ピンマイク指定のときは「そのトラックの音だけ」を混ぜて走らせる。無効になっているクリップも解析に含める。
2. **マイクの持ち主を自動で決める**: 各マイクを単独で聞いたときの音量（テロップの区間内を 30 ミリ秒ごとの RMS で測った 90 パーセンタイル）を比べ、その人の声が一番大きく入っているマイクを持ち主とする。差が 3 dB 未満なら決めずに、手動で指定するよう促す。
3. **話しているマイクを判定する**: マイクどうしの相対音量で、各テロップの区間に「どのマイクが話しているか」を決める。自信の低いテロップは音量で確定し、声紋の判定と食い違う所には印を付ける。
4. **計画を作る**: クリップごとに有効にするか無効にするかを決める。同時発話・相づちは両方有効、自信が低ければ両方有効に「マイクを確認」マーカー、マイクの無い人（カメラマンなど）の発話は全部有効、テロップが無い所と持ち主の無いトラックは触らない。
5. **実行する**: 有効・無効の切り替えは既存クリップ単位で、1 つの取引にまとめる（取り消しは 1 回）。
6. **話者が入れ替わる所の分割**: UXP にはクリップを分割する API が無いので、CEP の再生ヘルパーに「razor（分割）」を頼む。切れなかった所は両方のマイクを残し、「話す人が入れ替わる」のマーカーを付ける。

## 使った API と道具

- UXP: クリップの有効・無効の切り替え（取引の中の同期処理）、マーカーの追加。
- CEP（ExtendScript の QE DOM）: `track.razor(タイムコード)`。タイムコードは公開 API の `Time` で作る。
- サーバー: 音量の計算（ffmpeg で取り出した音声）、判定の合成、計画の作成。
- 安全弁: 実行の前後で映像トラックのクリップ配置を比べ、変わっていたら中止して「取り消しを切った数だけ」案内する。リンクされた音声を無効にしたときに映像まで変わっていないかを、この比較で守る。

## つまずきと直し方

- **古い再生ヘルパーが、知らない命令を「再生」として実行してしまう**。更新直後は、新しいサーバーとパネルに古いヘルパー（Premiere を再起動するまで古いまま）が組み合わさる。→ ヘルパーが起動時の確認で「razor ができる」と名乗り、パネルは名乗ったヘルパーにだけ分割を頼む。名乗らなければ「Premiere の再起動が要る」と案内し、代わりにマーカーで済ませる（詳しくは `feat-cutsrt-playback-helper`）。
- **分割の位置が 1 フレーム前後にずれる**。タイムコードに直すときに切り捨てが入る。→ フレームの頭ぴったりではなく、1/4 フレーム内側を渡す。
- **短い相づちを取りこぼす**。→ 30 ミリ秒ごとに測り、0.5 秒の相づちの中の 0.15 秒でも「回り込みより 6 dB 大きければ話している」と見る。
- **無音のテロップを「話している」と扱ってしまう**。→ 声が無いテロップは「話していない」扱いにした。
- **同じ音が 2 本のマイクに入っている素材で、持ち主が決まらない理由が分かりにくい**。→ 理由の文章を具体的にした。
- **Windows には再生ヘルパーが無い**ので、分割ができない。両方のマイクを残してマーカーで知らせる縮退運用になる。
- 実在のピンマイク素材で精度を測れなかったため、試験素材（2 人の架空の対談を、別々のマイクで拾ったように 2 本の音声に分けたもの）を作って確かめた。これは音響の精度の証拠にはならない。

## 結果と今の状態

- 試験素材での結果: 持ち主を自動で決められ（9.5/18.9 dB と 9.6/18.3 dB の 2 例）、テロップ 36 本・27 本が全て正しい話者に振り分けられ、無効にするクリップが声の有無と全部一致した。マーカーは 0。
- 実機で確かめたこと: 切り替えと映像の照合は通過。再生ヘルパーが razor を名乗ることも確認。
- **未確認**: razor が音声だけを切るか、狙ったフレームに入るか、リンクした音声を無効にして映像が変わらないか、取り消しで戻るか、本物のピンマイクの精度、Windows。実機で切る処理が動かなかった理由は、無音カットの切れ目と話者の入れ替わりが重なって切る処理が実行されなかったためです。
