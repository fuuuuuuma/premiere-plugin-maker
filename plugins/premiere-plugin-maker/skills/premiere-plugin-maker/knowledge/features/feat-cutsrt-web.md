## 何をする機能か

パネルの中で Web ページを開くタブです。素材サイトで探した画像や動画を、その場でプロジェクトに取り込み、アクティブなシーケンスの再生ヘッド位置（既定は V2）に置きます。ページの代表画像（`og:image`、`twitter:image`）か、直接ダウンロードできるファイルを保存して取り込みます。ログインが必要なファイルは、「Chrome」のボタンで普通のブラウザへ誘導します。

## 作り方

- `index.html` に `<webview>` を置く。マニフェストの `requiredPermissions.webview` で、開いてよいドメインを許可する。
- URL の入力欄、「開く」、「再読み込み」を自分で作る。
- 戻る・進むは API が無いので、履歴の積み重ねを自前で持つ。
- ページ遷移の開始を横取りし、ファイルのダウンロードに当たる URL なら、WebView には読ませず、パネル側の `fetch` で保存する。保存先はダウンロードフォルダで、ファイル名は `Content-Disposition` を優先し、同名ならタイムスタンプを付ける。同じ URL の再試行は抑える。
- ダウンロード中は WebView を隠す（文字化けの一瞬の表示を出さないため）。
- ブロックしたいドメインは、下部の入力欄にカンマ区切りで書き、`localStorage` に保存する。

## 使った API と道具

- UXP の `<webview>`、`uxp.shell.openExternal`（既定のブラウザで開く。マニフェストの `launchProcess.schemes: ["https"]` と対）、`fetch`、`localStorage`。
- 開発中の確認は、UXP Developer Tool のデバッグ画面（devtools）で `webview` 要素を直接評価するのが最も早い。ログには `[browser]` の接頭辞を付け、UXP のログを検索できるようにした。

## つまずきと直し方

- すべての遷移が `loaderror` になる（`domains` の書き方）: `"all"`、`["all"]`、キーの省略は、マニフェストの検証は通るが、実行時にすべての遷移を黙って拒否した。公式の資料では有効な値でも、Premiere では未実装だった。`https://*.example.com` は裸のドメイン（`example.com`）に一致せず、`https://*.com` のような TLD のワイルドカードだけが有効で、多階層のサブドメインにも一致する。そこで、主要な TLD を約 70 件列挙して実質的に全開放にした（Premiere 26.3 の実機で確認）。公式の資料の「有効な値」を信じず、実機で確かめる。
- 戻る・進む・再読み込みの API が無い: 自前の履歴スタックで補った。
- 添付ファイルの応答（ダウンロード）は `loaderror` か文字化けの描画になる: 上の横取りで解決した。さらに「弾き返しの途中の `loaderror`」がブロックの理由の表示を上書きしてしまうため、ブロックの状態を優先する条件を足した。
- ページとプラグインの間のメッセージの橋は無効: ページからパネルや Premiere を操作する経路は無い前提で設計する。
- 遷移のイベントで渡る URL がデコードで壊れる（署名付き URL は 1 文字違いで 403）: 壊れたときは再エンコードして再試行する。
- ログイン必須のファイルは保存できない: パネル側の `fetch` は WebView の Cookie（ログインの情報）を共有しない。ログインが要るダウンロードは、実ブラウザへ誘導する前提にする。
- 規約の注意: 開ける、保存できる、ことと、再利用してよいことは別。素材サイトの利用規約（自動での収集、直リンク、再配布の禁止）に従う。`feat-cutsrt-assets` を参照。

## 結果と今の状態

Premiere 26.3 の実機で、許可ドメインの挙動、素材サイトの表示、ダウンロードの横取りを確かめています（2026-07-18）。導入ガイドに Web タブの説明を足したのは v0.9.20 です。外部サイトへの `fetch` が CORS の制約を受けるかどうかは、「受けないはず」という前提のままで、確認の記録は見つかっていません。
