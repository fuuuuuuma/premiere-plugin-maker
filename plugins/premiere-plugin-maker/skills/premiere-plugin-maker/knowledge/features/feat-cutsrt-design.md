## 何をする機能か

タイムライン上で選んだテロップ（グラフィックのクリップ）を、一覧から選んだ別のデザイン（約 100 種）へ、本文はそのまま、1 回の操作で差し替えます。デザインには静止の見た目と、動き（イン・アウトのアニメ）の 2 系統があります。見た目の確認用に、一覧には見本の画像が出ます。

もとは Mac 専用の CEP 拡張（Effect & Design）でした。Cut & SRT の v0.11.0 で「Premiere の中で得があるものに絞る」方針のもと、タブとして取り込みました。拡張自体の構成は `feat-ed-overview` の系統にあたります。

## 作り方

1. エンジンは移植元のものを「写して」使う。写した部品は、元と同一であることをハッシュで検査するテストで守る。Cut & SRT 側の事情（Windows の違いなど）は、写した部品を書き換えず、起動役の別ファイル（`design_engine_run.py`）で吸収する。
2. 差し替えは、本文を保ったまま、土台の MOGRT（ドナー）をデザインに合わせて作り直し、`insertMogrtFromPath` でタイムラインへ入れ、元のテロップを外す。
3. 元のテロップの位置とモーション（動き）を読み、新しいクリップへ写す。キーフレームが付いているものは写さず、標準の位置に置いて 1 行の通知を出す。
4. 見本は、移植元の描画コード（`telop_svg.js`）をヘッドレス Chromium で描いた透過 PNG にして、全部を事前に作って同梱する。
5. 画面は、空の枠にスクリプトで部品を組み立てる。分類は横 1 列のスクロール帯、デザインとアニメの切り替え、設定は小窓ではなく「元の中身を隠して設定を出す」方式にした。

## 使った API と道具

- `SequenceEditor.insertMogrtFromPath(path, TickTime, 映像トラック, 音声トラック)`（取引に入れられない）、選択のライブ取得とクリップの削除アクション、効果の値の読み取り（Motion / Opacity）。
- MOGRT と `.prtextstyle` の内部（`ref-mogrt`、`ref-prtextstyle`）、キーの焼き込み（`ref-keyframe-interpolation`）。
- 事前生成の画像: ヘッドレス Chromium。生成用のスクリプトを用意し、全 100 種を一括で作る。
- 書体の検出: システム、利用者の書体、Adobe Fonts を全部見る。

## つまずきと直し方

- UXP の SVG は複雑な描画に対応しない（多段のグラデーション、フィルタ、グリフ単位の計測）。公式の既知の問題にも書かれている。見本を UXP で描こうとせず、ブラウザで描いた透過 PNG を同梱する。
- `<video>` での動画の見本は使わず、静止画にする。静止のフレームが必要なときは `Exporter.exportSequenceFrame` で PNG を作り、サーバーが `data:` の URL にして `<img>` に出す（上限 8MB）。
- 移植元も、元のテキスト位置を読まず標準の位置（横 0.5、縦 0.86）に描いていた。そのまま写すと、元の位置にかかわらず全部が同じ場所に来る。位置とクリップのモーションを読んで写す実装を足した。
- `insertMogrtFromPath` は、重なる区間を上書きしない: 当初は上書きされる前提だった（帯テロップでは先のクリップを潰したという記録もある）が、実機では元のクリップが残ったまま新しいクリップが足された。挿入の前に元を明示的に外す、重なりを検査して中止する、という作りにした。挿入は取引の外なので、取り消しは 2 回になる。この点は利用者に伝える。
- 「スタイルだけ貼り付け」は作れなかった: テロップの装飾は本文と一体のバイナリ（ソーステキスト）なので、スタイルだけを移す手段が無い。差し替え方式にした。
- 選択の作り方が版で変わる: 26.3 以降、`new ppro.TrackItemSelection()` で作った選択は後続の処理で「Connection to object lost」になる。ライブの選択を取って再利用する。古いコメントが残っていても、コードは新しい方に合わせる。
- Windows だけ「Basic Title.mogrt が見つかりません」: 写したエンジンはドナーの MOGRT を `/Applications` 配下でしか探さなかった。ハッシュ検査で写しを守るため、起動役の側で探索先を差し替え、Windows の Premiere のインストール先（`%ProgramFiles%\Adobe\Adobe Premiere Pro *\Essential Graphics`）も探すようにした。同時に、サーバーの出力を UTF-8 に固定した（Windows のパイプの既定は cp932 で、絵文字を書けず本文の読み取りが落ちる）。失敗の理由を画面に出すようにもした。Mac 専用に書かれた部品を写すときは、`/Applications`、`~/Library`、`subprocess` の文字コードを先に点検する。
- 書体が全部「書体なし」になる: Creative Cloud のサインアウトで Adobe Fonts が消えると、検査が全件で書体なしになる。書体の有無は毎回検出し、無いときは隠さず「書体なし」と理由つきで見せる。
- 写した部品の来歴に個人のパスが入り、配布物に載りかけた: 同期スクリプトでパスを `~` に置き換え、配る側を全部走査するテストを足した。

## 結果と今の状態

見本の事前生成、元の位置の引き継ぎ、元を外してからの差し替えは、Mac の実機で動いています。Windows では、上の修正の後に再確認を待っている状態でした。パネル内のファイルの読み込み順、MOGRT の上書きの前提、外部への `fetch` の CORS などは、実機での確認が残る項目として記録されています。
