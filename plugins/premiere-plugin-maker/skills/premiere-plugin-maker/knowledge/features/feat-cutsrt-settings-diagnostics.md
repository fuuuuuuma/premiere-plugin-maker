## 何をする機能か

配ったプラグインは、利用者の環境で何が起きているかが見えません。「動きません」だけの問い合わせでは、どのファイルで何が起きたかが分からず、やり取りが何往復にもなります。そこで、**設定を一か所に集め、診断を画面とターミナルの両方で見られるようにし、問い合わせ用の秘匿済みの診断パックを 1 クリックで作る**仕組みを持たせています。

## 作り方

- **設定**: 設定タブで変更すると、変更のたびに 0.5 秒のデバウンス（連続操作をまとめる）を置いて、全項目をサーバーへ送り、設定ファイルに保存する。秘密の値（外部サービスの鍵など）は応答に出さず、鍵は OS の保管庫に置く。
- **診断（画面）**: 「診断」の操作で、サーバー・依存（ffmpeg など）・AI のエンジン・モデルの準備状況を一覧にする。実行ファイルの版数、パネルとサーバーの版、通信仕様の版も出す。
- **診断（ターミナル）**: パネルが開かない、サーバーに届かない、といった場面のために、ターミナルから動く診断ツール（Mac は `doctor.command`、Windows は `doctor.bat`）を同梱する。常駐の状態、使用中の版、接続情報の整合、ffmpeg の有無と版数（サーバーが止まっていても）、サーバーへの疎通を一度に見る。画面をそのまま送ってもらえば原因が分かる。
- **サポートパック**: 設定タブの「サポートパックを保存」で、1 つの zip にまとめる。入れるのは、版数・OS・診断項目の OK/NG と、**許可された固定の形式のサーバーの運用イベントだけ**。字幕本文・辞書・設定・鍵・個人のパスは入れない（または伏せ字にする）。保存先と SHA-256 を処理ログに出す。元のログは書き換えない。利用者が送る前に zip の中身を自分で確かめられるようにする。
- **AI に聞くテンプレート**: 「困っていること・環境（OS／Premiere の版／プラグインの版／実行したファイル）・エラー全文・ここまで試したこと」を書き込む雛形を用意する。一度で直らなければ、新しい会話にせず同じ会話の続きに「どこまで実行したか・結果・新しいエラー全文」を貼る。
- **ログ**: パネルのログは、開いているタブに関係するものだけを表示する（共通のログは常に表示）。コピーは全タブ分（サポートの切り分け用）。サーバーのログは専用のフォルダ（Mac は `~/Library/Logs/CutSRTPlugin/`、Windows は `%LOCALAPPDATA%\CutSRTPlugin\Logs`）。大きくなったログは、中身を空にするのでなく**別名へ移して再起動**する（常駐プロセスが開いたままのファイルを壊さないため）。

## 使った API と道具

- サーバー側のルート: `/settings`（取得と保存）、`/doctor`（診断）、`/support-bundle`（サポートパック）。
- UXP のクリップボードと保存ダイアログ。
- 診断ツールは OS ごとのスクリプト。

## つまずきと直し方

- **設定の変更が、直後の実行に反映されない**。変更の保存がデバウンスで遅れ、直後に字幕の生成を実行すると前の値で動いた。→ 実行のリクエストに、そのとき必要な設定値を直接含めて送る。
- **「エラーが出ていないから成功」と見なす診断は危険**。無音カットで 0 件のカットを「成功」と扱い、気づけなかった例。→ 0 件や解析失敗は失敗として止め、閾値・基準トラック・実測した音量・無音の件数などの診断値を毎回出す。
- **診断を「失敗したとき用」だけにしない**。毎回出る値を増やしておくと、問い合わせのたびに原因が分かる。
- **自由に書かれたエラー文やログを丸ごと集めない**。個人のパスや字幕本文が混ざる。→ 収録する項目を許可リストで固定する。
- **ログの切り詰め**: 常駐のログを `truncate` すると、開いているファイルの位置がずれる。→ 移して再起動する。
- **版数の表示を HTML に直接書かない**。起動の JavaScript が走らないときだけ表示され、古い版を表示して誤診を招く。→ 版数は 1 か所の設定ファイルから読む（`feat-cutsrt-install-update`）。
- **サポートの導線をインストーラにも**: インストールに失敗したとき、原因のエラーログの末尾を画面に自動表示する。
- **外部のサービスへ送る設定がある場合**（例: 言語モデルの鍵）は、鍵を設定ファイルに平文で置かない。値は読み戻さず、「保存済みかどうか」だけを返す。

## 結果と今の状態

- サポートパックの設計と内容は、導入ガイドの記録では実機で確認済み。診断ツール（ターミナル版）は、問い合わせで画面を送ってもらう運用を前提に作られている。
- Windows の診断ツールは、サーバーが動いた報告までは確認済み。常駐の自動起動は未確認の記録が残る。

- Cut & SRT の導入ガイドの「困ったとき」とサポートの設計（2026-10）
- Cut & SRT の開発記録（設定の保存の競合、診断値の常時出力）
