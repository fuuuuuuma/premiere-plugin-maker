## 何をする機能か

無音カットは「声が無い所」を切りますが、話し言葉には「えー」「あのー」「まあ」のように**声はあるが内容のないつなぎ言葉（フィラー）**が混じります。この機能は、文字起こしから**フィラーの区間を見つけ、無音カットが切る範囲に足して一緒に切ります**。視聴者の要望で追加した**実験的な機能で、設定の既定はオフ**です。

関連して、フィラーと「言い直し」を見つけて**マーカーを付けるだけ**の機能（切らない）もあり、こちらを先に使って精度を確かめるのが安全な使い方です。

## 作り方

1. **文字起こしを生の形で取る**: 通常の字幕づくりでは、文字起こしの後処理で一部のフィラーが既に取り除かれる。取り除かれた語は検出器から見えないので、**後処理の前の生の結果も並べて保存**し、検出は生の方を読む（キャッシュの版を上げて、生の結果が無い古いキャッシュは自動で取り直す）。
2. **フィラーを見つける**: 固定の語彙（常にフィラーのもの、無音の前後にあるときだけフィラーのもの）を使う規則ベースの検出と、AI に「言い直し」と「フィラー」を 1 回の質問でまとめて判定させる検出を併用する。AI の判定を優先し、規則側は取りこぼしの補完にする。AI が失敗したときは、全体を規則ベースに切り替える（一部だけ混在させない。誤りの調査が複雑になるため）。使ったエンジンの名前は結果に残す。
3. **切る範囲に足す**: 見つけた区間を、無音カットの処理に「追加で切る範囲」として渡す（無音カットの本体に、追加範囲を JSON で受け取る引数を足した）。あとは通常の無音カットと同じく、XML を作り直して取り込む。
4. **マーカー版**: 同じ検出結果を、タイムラインのマーカーとして付ける。種類ごとに色を変える（言い直しは赤、フィラーは黄など）。マーカーの付け方は、追加→追加したものを取り直して色を付ける、の 2 つの取引。

## 使った API と道具

- 文字起こし（Mac は mlx-whisper、Windows は faster-whisper）の語単位の結果。
- 無音カット（`silence-cut` 部品）の追加範囲の引数。
- AI のエンジン（`feat-cutsrt-ai-engines`）。
- UXP: マーカーの追加と色の設定（`createAddMarkerAction`、`createSetColorByIndexAction`）。

## つまずきと直し方

- **フィラーが検出されなかった**: 後処理で削除済みの結果を読んでいたため、消えた語は原理的に見えなかった。→ 生の結果を並べて保存し、そちらを読む。
- **すでに無音カット済み（ジェットカット済み）の素材では、検出が 0 件になるのが正常**。0 件を異常と判断しない。
- **固定の語彙は過検出しやすい**（「ええ」「なんか」など、実際は返事や意味のある言葉のことがある）。強調の繰り返し（「本当に本当に」）を言い直しと誤判定するおそれもある。→ 既知のリスクとして据え置き、**人がマーカーで確認する前提**にした。だから切る機能は既定オフ。
- **言い直しの範囲が分かりにくい**: 「どこから言い直しているのか」が音声を聞かないと分からないという声があった。→ マーカーのコメントに「削除候補: 失敗した言い直し前の文言 → 言い直し後: 採用された文言」を入れ、そのまま消せる範囲をマーカーの区間にする。
- **編集点にぴったり合わない**: フィラーの区間は文字起こしの語時刻から出すため、前後に余りが出る。声の谷で補正する考え方（無音カットの記録）を併用する余地が残る。
- **標準の無音カットの正典（共有の部品）に追加範囲の引数を足していない**。同梱版にだけ足したので、共有の部品を更新するときに巻き戻さないよう、同期の前に新旧の判定を入れる。
- **設定の保存のずれ**: フィラーマーカーの設定を変えた直後に実行すると、前の値で動いた。→ 実行の要求に設定値を含める。

## 結果と今の状態

- マーカー版は、2026-07 に実素材で動作を確認した記録がある（マーカーが付き、言い直しも検出）。「フィラーまで拾いきれていない」「編集点にぴったり合っていない」という使用者の声を受けて、検出の方式を AI 主体に作り直した。
- **切る機能（追加範囲）は、実機での確認の記録が見つからない**。実験として既定オフで配った。
- 使うなら、まずマーカー版で件数と位置を目で確かめ、それから切る機能を試す。
