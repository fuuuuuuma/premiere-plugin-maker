## 何をする機能か

Cut & SRT は、動画編集者が Premiere Pro の中で使う「無音カット・字幕（テロップ）作り・話者の振り分け・デザイン適用・書き出しの送信」までを 1 つのパネルにまとめた UXP プラグインです。この棚は、その全体の作りを記録します。個々のタブは `feat-cutsrt-*` の別項目に分けてあります。

利用者が欲しかったのは「撮影した素材を渡したら、編集の下ごしらえが終わっている」状態でした。そのために 1 本のプラグインに多くの機能が載り、結果として「Premiere の中だけでは作れない処理」を手元の別プロセスに任せる形になりました。この構成はほかのプラグインを作るときの参考になります。

## 作り方

全体は 4 つの部品に分かれます。

1. UXP パネル（Premiere の中）。画面と、Premiere の操作（シーケンスの読み取り、クリップの移動、マーカー、効果）を受け持つ。HTML と JavaScript で書く。
2. ブリッジサーバー（手元の Python）。ファイルを作る処理（無音の検出、文字起こし、字幕の整形、話者の判定、外部サービスへの送信）を受け持つ。`127.0.0.1` の 3850 番だけで待ち受け、外のホストからは届かない。
3. CEP 補助（Premiere の中の別の拡張）。UXP に無い「再生・停止・クリップの分割（razor）」だけを ExtendScript で行う。
4. MCP の窓口（Python の標準入出力アダプタ）。Claude Code などの AI から、パネルと同じことを道具として呼べるようにする。

責任の分け方は「Premiere の中身をいじるのは UXP 側、ファイルを作るのと通知はサーバー側」です。サーバーから Premiere へ直接は命令できないので、パネルが一定間隔で「次の命令はありますか」と聞きに行きます（約 2 秒ごと）。CEP 補助も約 0.4 秒ごとに聞きに行きます。

### 通信と認証

- パネルからサーバーへは `fetch`。全部の呼び出しに `X-CutSRT-Token` というヘッダを付ける。
- トークンはサーバーが起動するたびに作り直す（16 バイトの乱数）。サーバーは握手用のファイル `server.json`（ポート・トークン・版・一時フォルダの場所）を、本人だけ読める権限で書く。場所は Mac なら `~/Library/Application Support/CutSRTPlugin/`、Windows なら `%APPDATA%\CutSRTPlugin\`。
- サーバーが再起動するとトークンが変わるので、パネルは 403 を受けたら `server.json` を読み直して 1 回だけやり直す。
- パネルとサーバーは `build_info.json` の `bridgeProtocol`（整数）を共有し、合わなければ「同じ版へ更新してください」と案内して接続しない。
- 一時ファイルの場所は `server.json` の `tmpDir` が唯一の受け渡し点。サーバーは「その配下で、想定した拡張子」のファイルしか読み書き・削除しない。
- 長い処理は「ジョブ」。`POST /jobs/<種類>` で開始（同時に動くのは 1 本。動いていれば 409）、`GET /jobs/<id>` で状態を聞く。ジョブ自体の失敗も HTTP 200 の中の `status: "error"` で返し、通信の失敗と区別する。

### タブの構成

パネルは上部のタブで機能を分けます。最終的な顔ぶれは、カット・テロップ・デザイン・素材・整列・話者・演出・送る・辞書・クリップ棚・FX スロット・Web・設定などです（版によって増減）。

## 使った API と道具

- Premiere: `premierepro` モジュール（シーケンス、トラック、クリップ、マーカー、書き出し、効果、MOGRT）、`ProjectConverter`（FCP7 XML と OTIO の書き出し）。UXP の `storage`・`fs`・`os`・`shell`・`clipboard`・`localStorage`・`<webview>`。
- サーバー: Python 標準の `http.server`（`ThreadingHTTPServer`）、ffmpeg、文字起こしエンジン（Mac は mlx-whisper、それ以外は faster-whisper）、AI の CLI。
- 常駐: Mac は LaunchAgent、Windows はタスクスケジューラ。
- 検証: Python の unittest、Node の `vm` を使ったパネルの試験、ヘッドレス Chromium でのパネルの崩れ検査。
- キットの部品: `local-server`（サーバーの骨組み）、`mcp-bridge`、`cep-helper`、`ui-kit`、`logger`。

マニフェストの要点は `core-manifest-permissions` を参照してください。この作りでは、手元のサーバーへ `fetch` するために `network.domains: "all"` が要り、ファイルの読み書きに `localFileSystem: fullAccess` が要りました。

## つまずきと直し方

- 起動直後はサーバーよりパネルが先に立つ。接続失敗は 4 秒間隔で 5 回まで自動でやり直し、それでもだめなら原因つきで表示する。
- 初期化が二重に走る・宣言前の変数を踏む（評価時の `readyState` が想定と違う）。起動処理はファイル末尾に 1 回だけ置き、「初期化済み」の印を持たせる。
- `require` の相対パスは UXP で使えない。サブファイルは HTML の静的な `<script src>` で順に読み、全部が同じグローバルを共有する。
- 編集した場所と、Premiere が実際に読む場所が別のフォルダだった。「直したのに変わらない」ときは、まず稼働中のプロセスのパスとパネルの読み込み元を確かめる。
- 版数は 5 か所（マニフェスト、`build_info.json`、サーバーの版、パネルの版表示、変更履歴）を揃える運用にした。HTML に版数を直書きしない。版数は Mac と Windows の両方に関わる変更のときだけ上げる（片方だけの小さな修正では上げず、同じ版の行に追記する）。
- 同じ版の入れ直しでは更新が届かない仕組みがある（`feat-cutsrt-install-update` を参照）。

## 結果と今の状態

Mac では、カット・テロップ・整列・辞書・デザイン・話者の振り分けなど主な機能を、作者が Premiere の実機で確かめています。Windows は利用者からの報告で、カット・テロップ・整列・クリップ棚・FX スロットが動いたとの連絡がありました。一方、演出タブの一部（画角の変更の自動配置など）、リンクした音声の無効化、取り消しの一部、ピンマイクの本物の録音での精度、外部サービス送信の一部は、実機での確認が残っています。このキット自体は Premiere の実機では通していません。
