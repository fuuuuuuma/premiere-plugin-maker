## 何をする機能か

Premiere Pro に UXP パネルを作らずに、編集の「いちばん手間のかかる 2 つ」を AI のスキルとして使えるようにしたものです。

- `/cut`: Premiere から書き出した Final Cut Pro XML を読み、しゃべっていない区間を取り除いた XML を出力する。
- `/srt`・`/srt-fast`: 音声（WAV）を文字起こしし、AI が意味の切れ目で改行して、時刻つきの字幕ファイル（SRT）を作る。`/srt-fast` は速さ優先の版。

Cut & SRT のパネルで同じことをする前身にあたり、パネルの中身（`feat-cutsrt-cut`・`feat-cutsrt-telop-srt`）はここで固めた考え方を引き継いでいます。

## 作り方

### 配布の形

リポジトリ直下に、Claude Code 用の `.claude-plugin/`、Codex 用の定義、AI 向けのスキル本体（`skills/<名前>/SKILL.md`）、実際に動く Python スクリプト（`scripts/`）を置きます。同じ手順書を開発環境用の `commands/*.md` と配布用の `skills/` の 2 通りで持つので、片方だけを直して食い違わせないよう注意が要ります。

配布の履歴は、Claude Code 用プラグイン化 → Codex 対応 → Antigravity・Grok 向けの追加、の順でした。Codex 対応のときに確かめた事実が 2 つあります。Codex は `.claude-plugin/marketplace.json` もそのまま読むこと、そして `${CLAUDE_PLUGIN_ROOT}` の置き換えをしないこと。後者は Claude Code でも、`ROOT="${CLAUDE_PLUGIN_ROOT:-...}"` のように値の既定を付けた書き方だと置き換わりません。そのため、スクリプトの場所は「候補を順に探す」書き方（`find` で導入先を探す連鎖）にしています。

### /cut の考え方

- 無音の検出は、既定では声が入っているトラック（A1）の音声だけで行います。ピンマイクで複数人を別トラックに録っているときだけ、対象のトラックを明示します。BGM や環境音が常に鳴っているトラックを対象に入れると、いつまでも無音にならずカットが 1 件も出ません。
- 全トラックに同じ位置で編集点を入れます。ただし、トラックごとに素材の開始位置（ソースオフセット）が違うので、`オフセット = 素材の入り点 − タイムライン上の開始位置` をトラック別に持ちます。全トラックに同じ入り点を当てるとずれます。
- 前後に残す余白の合計が最小の無音の長さ以上だと、すべての無音が余白に食われて 1 フレームも切れません。スクリプトが警告を出します。
- 終了コードで結果を約束しています（下の表）。

| 終了コード | 意味 |
|---|---|
| 0 | 切れた |
| 3 | カット 0 件（成功扱いにしない） |
| 4 | 対象トラックの音声を 1 本でも取り出せなかった。XML は書かない |
| 5 | 書き出した XML に映像クリップが無い（マルチカムなど）。XML は書かない |

「新しいシーケンスはできたが中身が未カットのまま」という利用者の報告を再現して、成功扱いをやめました。失敗は静かに通さず、診断の数字（実測した音量・基準トラック）を添えて止めます。

### /srt・/srt-fast の考え方

1. 文字起こしは GPU を使う方式（mlx-whisper）で 1 回通して行います。以前は音声を 3 つに分けて並列に転写していましたが、転写が十分速くなると分ける意味が無くなり、境目の欠落や幻聴（終了時に出る「ご視聴ありがとう」など）の対策が不要になりました。分ける軸を「音声の時間」から「文字起こし後のテキストの意味」に変えたのが /srt-fast の転換点です。
2. 字幕の改行は AI が文脈で判断します。形態素解析のライブラリ（MeCab など）は使いません。複合動詞やカタカナ語を途中で割ってしまうため、AI の判断のほうが分断が圧倒的に少なかったためです。
3. 時刻は、AI が整えた行の文字列と、文字起こしの単語の列とを差分アルゴリズム（difflib）で全体合わせして割り当てます。行側で固有名詞を直しても時刻がずれません。以前の「少し先を探して前に進む」貪欲な合わせ方は、後ろへ後ろへとずれが溜まり、最後が音声より数秒はみ出す不具合の原因でした。
4. 組み立てたあと、機械が 1 行の文字数（25 字超）や文頭に来てはいけない文字を検査し、該当行だけ AI が直して再実行します。AI の改行は実行ごとに出来が変わる（同じ入力で 25 字超が 0% の回も 5% を超える回もあった）ので、この修復の輪は省けません。
5. AI への並列の依頼は、全文を 1 人に任せず小分けにして同時に出します。全文を渡すと脇道（自己検証）に逸れて 95 秒かかったものが、2 分割で 24 秒になった実測があります。依頼文の最後に「書き終えたら見直さず終了」と書くのも効いています。

## 使った API と道具

- Premiere の API は使いません。受け渡しはすべてファイルです（FCP7 XML → スクリプト → XML、WAV → SRT）。XML の形式は `ref-fcp7-xml` を参照。
- 無音の検出と音声の取り出しに ffmpeg を使います。実行前に入っているか確かめます。
- 文字起こしに Whisper 系（Mac の Apple Silicon では GPU 版）を使い、結果をキャッシュして `/srt` と `/srt-fast` で使い回します。
- 固有名詞の辞書は利用者ごとの設定ファイル（`config/` 配下で、リポジトリには載せない）に分けます。
- 任意機能として、意味のある「もう」を字幕に残す処理があります（外部の判定サービスを使い、既定はオフ）。

## つまずきと直し方

- 個人情報の混入: 固有名詞の辞書、チャンネル別のパターン、設定が、最初は本体のスクリプトや文書に直接書かれており、公開リポジトリに載っていました。設定ファイルへ分け、本体の辞書は汎用の置き換え 1 件だけにして、公開履歴ごと書き換えました。履歴の書き換えは、ファイルの内容の置換だけではコミットメッセージが残るため、内容とメッセージの 2 回に分けて行い、最後に全履歴を検索して確かめます。
- 公開物に個人の絶対パスが残る: 開発環境用の手順書に、個人の場所の候補が書かれたまま公開されていた例があります。公開前に絶対パスを検索します。
- 速度を上げるつもりで仕組みを足しても速くならない: 起動の手間を嫌って仕組みを削ったとき（複数段の自動化をやめて直接並列に出した）に初めて速くなりました。速度の測定は、同じ音声・同じ条件で、実行ごとのばらつきを前提に行います。
- カット 0 件の原因は 1 つではありません（しきい値が厳しい、基準トラックに音声が無い、BGM が常に混入している、余白が大きすぎる、リンク切れ）。同じ画面になるので、診断の数字を見て切り分けます。
- 書き出した XML の素材リンクを解決できないときは、リンクの要素ごと取り除きます。切れた ID が残ると Premiere の読み込みが壊れるおそれがあるためです。

## 結果と今の状態

- /cut は終了コードの契約と、トラック別のオフセット、合成 XML の整合（リンク・連続性）の検査が済んでいます。
- /srt-fast は同じ 221 秒の音声で、並列版 175 秒（25 字超 15%）から、テキスト分割版 154 秒（25 字超 0%）、さらに直接並列版で約 55 秒まで短縮されました。この数字は Mac での測定です。Windows の実測はありません。
- Premiere に取り込んだ最終の見た目の確認は、Cut & SRT 側のパネルで行った記録が主です。このスキル単体を複数の環境で通した記録は揃っていないため、status は partial です。
- 「パネルを作るか、スキルとファイル受け渡しで済ませるか」の判断材料になります。UI が要らず、入力と出力がファイルで決まる作業はスキルで足ります。取引やタイムラインの直接操作が要る作業は、パネルや MCP（`feat-premiere-agent-kit`）の領分です。
