## 何をする機能か

アクティブなシーケンスから「しゃべっていない区間」を見つけて取り除いた、新しいシーケンスを作ります。元のシーケンスは触りません。編集者が最初にやる作業を機械に任せるための、Cut & SRT の中心の機能です。

## 作り方

流れは「書き出す → サーバーで切る → 読み込む」の往復です。

1. パネルが `ProjectConverter.exportAsFinalCutProXML` でシーケンスを FCP7 XML（xmeml）に書き出す。一時フォルダは `server.json` の `tmpDir`。
2. サーバー（Python）が XML を読み、音声トラックのメディアを ffmpeg で取り出し、無音区間を検出する。
3. 検出した無音を除いたクリップ列で、新しい XML を組み立てる。
4. パネルが `project.importFiles` で XML を読み込み、できたシーケンスを探して開く。

### 無音の検出（包絡方式）

最初は ffmpeg の `silencedetect` を使いましたが、「前を詰めて後ろに余韻が残る」非対称が全部のカットで出ました。発話の頭は急に立ち上がるので正確に測れる一方、終わりはゆるやかに減衰するため、音量の判定が約 1 コマ遅れて落ちるからです。時間を反転して逆向きに検出しても消えませんでした。

そこで検出を作り直しました。生の音声（16kHz、モノラル）を ffmpeg からパイプで受け取り、20 ミリ秒の窓の音量（RMS）を並べた「包絡」を作ります。その包絡が -45dB を横切る点を、前側も後側も同じ基準で決めます。こうすると、前後に残す余白（パディング）を対称にしたとき、残る量が前後で本当に同じになります。実測では、残る量が前が 1.93 コマ、後ろが 1.95 コマ（差 0.02 コマ）でした。64 分の素材も完走しました。

### 時間の数え方（fps の規則）

FCP7 XML は、コマの速さを「整数の timebase と NTSC かどうか」でしか書けません。可変フレームレートの素材（スマホ撮影の実 29.998fps など）から自動で作られたシーケンスは、29/FALSE のような中途半端な値で書き出されることがあります。

守る規則はこれです。

- 秒とコマの換算は、必ず XML が宣言する timebase で行う。
- 実際の fps や実メディアの長さは、「解析の窓が素材の終わりを超えないようにする」クランプと、fps を整える判断にだけ使う。
- 実 fps で換算すると、1 秒ごとに少しずつずれ、1 時間近い素材では数秒〜十数秒の差になる。コマの値と `pproTicks` の基準が同じ XML の中で混ざると、Premiere は ticks を優先してカットが崩れる。

### 部分複製のときの XML の規則

Premiere の書き出しは、同じ素材を何百のクリップが参照しても、`<file>` の完全な定義（パスと長さ）を文書全体で最初の 1 回だけ持ち、残りは `<file id="…"/>` の空の参照にします。タイムラインの一部だけを複製するコードは、この唯一の定義を落とすと、実体パスが 0 個の XML を作ります。Premiere はそれをエラーも出さずに読み込み失敗にするので、症状が「新しいシーケンスが増えない」だけになります。

- 複製の前に、元の木から `file id` ごとの完全な定義を取っておく。
- 出力では、文書全体で最初に出る箇所に定義を 1 回だけ置く。
- 書き出す前に、「空の参照より前に完全な定義があるか」を検査する。解決できなければ XML を書かずにエラーにする。
- 「完全な定義かどうか」は `<pathurl>` の有無ではなく、`<file>` が子要素を持つかで判定する（テロップなどのグラフィックは実ファイルを持たない）。

### 終了コードと「0 件は成功にしない」

カットのスクリプトは終了コードで結果を伝えます。

| 終了コード | 意味 |
|---|---|
| 0 | 成功 |
| 3 | カット区間が 1 つも無い（成功扱いにしない） |
| 4 | 音声を取り出せなかった |
| 5 | 書き出し XML に映像クリップが無い（マルチカムなど） |

「新しいシーケンスはできるが中身が未カット」という報告の原因は、実は 5 通りありました（閾値が厳しすぎる、音声素材のリンク切れ、音声トラックがネストやマルチカム、ffmpeg の抽出失敗、余白が無音の長さを食い切る）。全部が同じ症状に見えたのは、「カット 0 件」を成功として未カットの XML を出し、ffmpeg の戻り値も見ていなかったからです。0 件と抽出失敗を別の型で扱い、診断値（閾値、基準にしたトラック、実測のピーク、無音の件数）を成功時にも毎回ログへ出すように直しました。

## 使った API と道具

- `ProjectConverter.exportAsFinalCutProXML`（Premiere 26.2 以降）、`project.importFiles`、`SequenceSettings.getVideoFrameRate()`（メソッド。プロパティではない）。
- サーバー側: ffmpeg、numpy（累積和で窓の RMS を線形時間で出す）、xml の木の操作。
- 設定: 閾値（dB）、最小の無音の長さ、前後の余白（個別に指定可）、基準にする音声トラック、転写に使う音声（全トラックを足すか、A1 だけか）。

## つまずきと直し方

- 末尾の約 100 秒だけ未カット: 宣言 timebase 29 と実 fps 29.998 の食い違いで、解析窓が素材の外を指していた。実メディアの長さでクランプして解消。
- 後半ほど位置がずれる: 秒とコマの換算を実 fps に統一したのが誤りだった。宣言 timebase に統一し直した（「2026-06 の訂正の再訂正」として、コマと ticks を全部宣言 timebase で書く規則に確定）。
- フレームレートを取れず黙って 30 に落ちる: `SequenceSettings` にはフレームレートのプロパティが無く、`getVideoFrameRate()` というメソッドの戻り値からしか取れない。存在しないプロパティを読んで `undefined` になり、30 を「実測値」としてサーバーに送って正しい 60fps の XML を壊していた。検出に失敗したら値を送らない、サーバー側でも宣言と 8% 超食い違う値は拒否する、の二重防御にした。
- 表示の同期ズレバッジ（+17 など）: Premiere が 29.998fps を `<rate>` 29 に切り捨てて書く。元を断つには、標準の 30fps か 29.97fps のシーケンスで編集するか、素材を固定フレームレートに変換してから編集する。
- 時間の単位を混ぜる: XML の `<in>`/`<out>` はクリップ自身の rate、`<start>`/`<end>` はシーケンスの rate。混在レートでは素材位置がずれる。
- 稼働しているのが別のフォルダ・別のコピー: 無音カットのスクリプトは、正典のコピーとプラグイン同梱のコピーの 2 つがあり、実際に動くのは同梱側だった。直したら両方に同じ内容を入れ、差分が無いことを確かめる。
- カットの結果が空になったとき、数分かけた解析結果を捨てない。理由と手動の取り込み手順を添えて返す。

## 結果と今の状態

包絡方式の前後対称、宣言 timebase の統一、部分複製の完全定義の規則は、Premiere の実機で確かめた記録があります（長尺素材を端から端まで実測）。フィラー（言いよどみ）を切る実験機能は別項目（`feat-cutsrt-filler-cut`）です。マルチカムの自動切り替えは見送りました。マルチカムやネストが音声の基準トラックにある素材は、終了コード 5 で止めて理由を出します。
