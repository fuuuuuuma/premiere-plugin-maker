## 何をする機能か

字幕づくりのうち、「意味で区切る改行」は文脈の判断が要る仕事です。Cut & SRT は、**利用者が自分のパソコンに入れて自分のアカウントでログインした AI のコマンド（CLI）**を子プロセスとして呼び、改行の判断や辞書の補助を任せます。プラグイン自身は AI の鍵を持ちません。使えるエンジンは設定で選べ、自動のときは決められた優先順で試します（Codex、Claude、Antigravity、Gemini、Grok、ローカルのモデル）。ローカルのモデルは、AI の CLI が無い環境の代わりになります（Apple シリコンの Mac は mlx、Windows は Ollama）。Intel の Mac は完全ローカルの改行ができず、AI の CLI が事実上必須です。

## 作り方

- **エンジン情報は 1 か所に集める**: 名前・実行ファイル・認証の種類（ログイン／API キー／不要）・必要な環境変数・画面の選択肢・既定のモデル・思考の深さを、1 つの登録簿にまとめる。サーバーの許可リストも画面の選択肢も、そこから導出する。エンジンを足すと、検査の対象にも自動で入る。
- **起動**: プロンプトは**標準入力かファイル**で渡し、コマンドの引数に載せない。作業フォルダは「空」または指定なし。モデルの応答は決まった形（JSON など）で受け取り、壊れていれば再試行する。
- **使えるかの確かめ（プローブ）**: ログイン済みかを、短い質問を実際に投げて確かめる。**確かめる経路は本番と同じ**にする。上限（約 18 秒）を設け、時間切れはプロセスのグループごと止める。ログインしていないとは断定せず、「確認できない」と表示する。
- **失敗の翻訳**: 利用上限、レート制限、認証切れ、時間切れを別々の分かりやすい文にする。CLI の生のエラー文をそのまま見せない（利用上限の本当の理由が長い文に埋もれるため）。
- **設定からの再確認**: 「再接続」の操作で、確認結果のキャッシュを捨てて再検査する。

## 使った API と道具

- サーバー側のサブプロセス管理、エンジン登録簿、各 CLI（Codex・Claude Code・Gemini・Grok・Antigravity）、Ollama または mlx のローカルモデル。
- ルート: `/engine/health`（状態）、`/engines/recheck`（再検査）、`/engine/repair`（修復の実行）。

## つまずきと直し方

- **Antigravity の「応答確認」が英語の羅列になった（回帰）**。原因は、別の CLI（Claude）の修正が共有していた検査用の最終行から本文を抜いたこと。Antigravity だけが標準入力を読めず、本文ゼロで起動して異常終了し、使えない扱いになった。**差分に「antigravity」の文字は 1 度も出てこない**ので気づきにくかった。→ 本文が、引数・標準入力・ファイルのどれかで必ず届くことを、**実際に送られる引数と標準入力を捕まえて**、登録簿のエンジンを総当たりで検査するテストを足した（修正前のコードに当てると赤くなることも確認）。教訓: 転送方式を変える修正は、その方式を使えない兄弟がいないかを必ず確かめる。契約が成り立つ層（実際に送られるもの）で検査する。
- **Windows で長い日本語のプロンプトが壊れた**（`.cmd` の経由）。→ 本文を引数に載せず、標準入力かファイルにする。検査も同じ経路で。「検査は成功、本番は破壊」になるのは、検査と本番の経路が違うとき。
- **ログインを完了しても、再起動まで直らない**。ログインの確認結果が False のとき、それをサーバーの動いている間ずっと覚えていた。→ 短い有効期間（TTL）にし、画面の「再接続」で明示的に捨てる。
- **ジョブが失敗したのに「通信が切れた」と表示された**。ジョブ状態の応答は HTTP 200 の中に `status: "error"` を持つ。通信層でエラーキーだけ見て例外にすると、状態の確認の層が通信断と取り違える。→ 通信の成功／失敗とジョブの成功／失敗を別の層で判定する。
- **システム指示と質問を同じ引数で渡すと、モデルが役割を取り違える**。→ 規則と会話を見出しで分け、「内部の規則は質問ではない・黙って適用する」と明記する。
- **1 メッセージ 1 プロセスの CLI は会話が続かない**。→ 直近の履歴を、大きさと役割を制限して毎回渡す。
- **CLI の探し場所**: Windows の Node のバージョン管理の下や、Mac のユーザーの `bin` など、PATH に無い場所にある。→ OS ごとの探す場所の一覧を 1 か所に持つ。
- **ローカルモデル（Ollama）の「思考」が応答に漏れる個体がある**。→ 思考オフの指定だけでなく、プロンプト側にも思考オフを併記する。
- **費用と規約**: AI の CLI は利用者自身のアカウントの利用枠や料金を使う。字幕の本文が各サービスへ送られることになる点を、設定の説明に書く。ローカルのモデルを選べば本文は外へ出ない。

## 結果と今の状態

- 回帰の修正は 2 つの配布ラインに入れ直して配った。自動テストで、全エンジンについて「本文が必ず届く」を検査している。
- Windows は実機の症状に基づいて直した記録があるが、全エンジンの確認が揃っているわけではない。
