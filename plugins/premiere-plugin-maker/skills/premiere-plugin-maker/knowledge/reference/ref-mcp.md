## 仕様

MCP（Model Context Protocol）は、AI の道具（Claude Code・Codex など）が外のプログラムの機能を呼ぶための決まりです。プラグインに MCP の口を付けると、AI が「選択中のクリップを読む」「マーカーを打つ」といった操作をパネルに頼めます。開発中の確かめにも使えます。

**仕組み**

```
AI ── 標準入出力の JSON-RPC ──► MCP のアダプタ（Python、標準ライブラリだけ）
                                   │ 手元のサーバーの /agent/... を呼ぶ（server.json の合言葉つき）
                                   ▼
                          サーバーの待ち行列（メモリ上）
                                   ▲ パネルが 2 秒ごとに「次の命令」を取りに来る
                                   │ 実行して結果を返す
                                   ▼
                          待っていた呼び出しに結果が戻る（成功 200／パネルの失敗 502／無応答 504）
```

- アダプタは、`initialize`・`notifications/initialized`・`tools/list`・`tools/call` に答えます。プロトコルの版は、相手（AI）が申し出た版が自分の対応表にあればそれを、無ければ自分の最新を返します（キットは 2025-06-18・2025-03-26・2024-11-05 に対応）。
- **サーバーからパネルへは送れません**（push が無い）。パネルが一定間隔（2 秒）で取りに行く**ポーリング**です。パネルを閉じていると、命令は取られず 504「パネルが応答しません」になります。
- 待ち行列は、件数と期限に上限を付けます（例：50 件・300 秒）。再起動で消えます。
- 命令ごとに待つ時間の上限を決め、MCP の側の timeout はそれより数秒長くして、タイムアウトのときもサーバーの案内文を受け取れるようにします。
- 長い処理（字幕の生成など）は、「開始」だけを返し、進み具合は別の道具（ジョブの状態を読む）で見ます。
- パネル側の実体は、画面のボタンと**同じ関数**を呼びます。ドメインの処理を二重に書きません。

**道具（tool）の書き方**

- 道具には `name`・`description`・`inputSchema`（JSON Schema、`additionalProperties:false`）を付けます。
- **道具の名前に、AI の側が自動で付ける接頭辞（Claude Code なら `mcp__<サーバー名>__`）を自分では付けません**（二重になるため）。名前は、何をする道具かが分かる短い言葉にします。
- 説明文には、AI への運用の指示を入れます：「実行の前に件数を伝えて確認する」「Cmd+Z で戻せる」「先に一覧の道具で、実在する名前を調べる」。Premiere を変える道具は「利用者の実行の指示があるときだけ」使う、と書きます。
- 設定を返す道具は、鍵の名前で秘密と判定したものを「設定済みかどうか」の真偽値に置き換え、エラー文に token が混ざらないよう最後に伏せ字にします。

**登録**

- **設定ファイルを手で書き換えません。** 各 CLI の登録の命令に任せます：
  - Claude Code：`claude mcp add <名前> --scope user -- python3 <アダプタの絶対パス>`
  - Codex：`codex mcp add <名前> -- python3 <アダプタの絶対パス>`
- 何度実行しても同じ結果になるよう、先に `remove` してから `add` します（`remove` の失敗は無視してよい）。試し実行（何をするかの表示だけ）を既定にして、`--apply` で実行します。入っている CLI にだけ登録します。
- 登録のあとは、**新しいセッションで** health の道具を 1 回呼んで、つながりを確かめます。

## 例

アダプタが握手のファイルを探す順（これが大事）：

1. 環境変数で指定されたファイル
2. アプリのデータフォルダの `server.json`
3. アダプタのファイルの隣の `ready`

## 注意

- **古い握手のファイルで 403 が続いた事故**：リポジトリから起動したアダプタが、隣に残っていた古い `ready` の token を使い、全ての道具が恒久的に 403 を返しました。パネル側は正常なので誰も気づかず、2026-08 の計測で、あるエンドポイントの 403 が 13,310 回・200 が 94 回でした。上の順（アプリのデータフォルダの `server.json` を先に）にし、403 を受けたら一度だけ読み直して再試行します。
- パネルのポーリングは `setInterval` なので、実行中の命令があっても次の取りに行く時刻が来ます。命令の多重実行を防ぐ仕組みがコードに見当たりません。AI が 1 つずつ呼ぶ前提では問題になりにくいですが、気に留めます（推測）。
- 件数の多い変更の道具は、1 回の上限（例：マーカー 50 か所、コマの書き出し 20 枚）を設けます。
- AI にできること・できないことを、道具の説明で正直に伝えます（core-capabilities）。
- 実機で確かめたのは Mac の Claude Code 側です。Codex への `--apply` と、Windows のアダプタは、確かめていません。
