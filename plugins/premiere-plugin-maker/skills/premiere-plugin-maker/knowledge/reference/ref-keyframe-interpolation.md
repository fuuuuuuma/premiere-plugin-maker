## 仕様

ExtendScript でキーフレームを打ち、`param.getValueAtTime(t)` で途中の値を読んで、式を当てはめた結果です（Premiere 26.5、2026-09-19）。

**数値のパラメータ（時間方向）**

区間（隣り合う 2 つのキーの間）の形は、**始まり側のキーの補間だけ**で決まります。終わり側のキーの種類は関係ありません。

| 始まりのキーの補間 | 区間の形 |
|---|---|
| linear（0） | 直線 |
| hold（4） | 次のキーまで値が一定 |
| bezier（5） | 3 次ベジェ曲線。制御点は (0,0)・(1/6,0)・(5/6,5/6)・(1,1) |

bezier は「出だしがゆっくりで、終わりは区間の傾きのまま」という左右非対称の形です。0 から 100 へ 1 秒かけるとき、0.5 秒の値は 43.75 です。この式で、測定値との差は 0.0005 以内でした。ExtendScript で打つ `easein`・`easeout`・`auto` は、**すべてこの bezier になります**（別々の形にはなりません）。

**空間のパラメータ（位置など `[x, y]`）**

値だけでなく、動く**道筋そのものが曲がります。** 各区間は 3 次ベジェで、

- 中間のキーの接線 ＝ （次のキー − 前のキー）÷ 6
- 端のキーの接線 ＝ 隣のキーへ向かう方向の 1/6

です。進み方は、「道のりの割合」に、上の時間の形（bezier）を掛けたものです。直線の補間なら測定値と完全に一致します（誤差 0）。bezier の区間では、道筋に沿った進み方に最大 0.005 ほどのずれが残ります（原因は分かっていません。終わりの傾きを 1.0〜1.38 にすると合うが、規則は見つかっていない）。

**行き過ぎの正体**

位置のキーで「設計の約 2 倍行き過ぎる」現象は、この空間の曲線が原因です。設計では 0.525 で止まるはずが、0.578 まで出ました（スライドの設計 5% が実測 9.4%）。対策は、設計の行き過ぎを半分にしておくことです。

**UXP の制約**

- キーを打つには `createSetTimeVaryingAction(true)` が必要で、これで（再生ヘッドが 0 のとき）時刻 0 に余分なキーが増えます。
- **補間は同じ取引の中では変えられません。** `createSetInterpolationAtKeyframeAction` も `setTemporalInterpolationMode` も、エラーなしで効きません。別の取引に分ければ効きますが、取り消し（Cmd+Z）が 2 回必要になります。

## 例

**焼き込み（bake）**：Premiere が描く曲がり方を、**1 コマごとの直線のキー**にして、1 回の取引で書きます。取り消しは 1 回で済みます。

- 数値の**直線**の区間：両端のキーだけ。
- **hold**：次のキーの直前の 1 コマに、同じ値を置く。
- **bezier** と **位置**：1 コマごとにキーを置く。
- 同じ時刻のキーは、後ろの値を採る（ExtendScript で同じ時刻に打ったときと同じ）。
- 1 本のトラックのキーは 1200 個まで。長い繰り返しは、何コマおきかに間引く。

```js
// bezier(5) の時間の形（制御点 (0,0) (1/6,0) (5/6,5/6) (1,1)）
function easeBezier(x) {
  if (x <= 0) return 0; if (x >= 1) return 1;
  const cubic = (a, b, u) => { const v = 1 - u; return 3*v*v*u*a + 3*v*u*u*b + u*u*u; };
  let lo = 0, hi = 1;
  for (let i = 0; i < 48; i++) { const m = (lo + hi) / 2; if (cubic(1/6, 5/6, m) < x) lo = m; else hi = m; }
  return cubic(0, 5/6, (lo + hi) / 2);
}
```

精度（16 種類の動き × 各 89 コマで、ExtendScript で打った経路と焼き込みの経路を比べた結果）：14 種類は差が 0.04 以下。残り 2 種類（横スライドと弾む落下）は、位置が行き過ぎて戻る 1〜2 コマで、720p の画面で文字が 4〜6 画素ずれました（見て分かる差ではないので、この精度で確定）。速さは、20 秒のテロップに繰り返しの動き（キー 589 個）を当てて、依頼から結果まで約 3 秒、取り消し 1 回でした。

## 注意

- **2 つだけのキーの終わりの easein は効きません。** 区間の形は始まりのキーで決まるので、終わりのキーに減速を指定しても、減速の形になりません。減速させたいときは、中間のキーを 2 本足して作ります（時間 0.45・0.75、値 0.70・0.94 の例。作者のメモによる記録で、コードでの裏付けは見つかっていません）。
- 取り消しの実測：取引 1 回 ＝ Cmd+Z 1 回です。複数のクリップに当てても 1 回です。同じ取り消しの名前を付けても、2 回の取引はまとまりません。
- キーを消す `createRemoveKeyframeAction` は、作る時点でキーの存在を確かめるので、**同じ取引で足したキーは消せません**（"keyframe doesn't exist"）。範囲で消す `createRemoveKeyframeRangeAction` は通ります。
- 値は `getStartValue` の戻りも、キーの `value` も、`{value: 値}` と一段包まれています（位置は PointF）。
- 拡大・回転の中心（アンカー）が画面の中央のままだと、下に置いた文字は中央に向かって弧を描いて飛びます。キーを打つ前に、アンカーを文字の位置に移し、見た目が変わらないように位置も `(T − A) × scale/100` だけ動かします（ref-prfpset の注意も見てください）。
- この式は Premiere 26.5 の Mac での実測です。他の版や Windows で変わらないことは確かめていません。
