## 要点

- 最初に OS（Windows か Mac）を聞く。以降の手順・コマンド・パスはその OS の表から出す。
- 6 つの質問を、1 問ずつ、選択肢をつけて聞く。一度に何問も出さない。
- 答えの言葉で知識の棚を検索し、使える知識・部品・過去の機能の記録を選ぶ。
- 「できないこと」の表（`core-capabilities`）に当てて、無い操作なら先に正直に伝え、代わりの手を選んでもらう。
- 計画（作るもの・雛形と部品・最低版・必要な権限・確かめ方・できないこと）を平易な言葉で見せて、承認をもらってから作る。

## 詳しく

### 6 つの質問

1. **何をしたいか**（1 文で）。
2. **何に対してか**: 選んだクリップ／シーケンス全体／プロジェクトの素材／マーカー／書き出し。
3. **どう動かすか**: パネルのボタン／メニューのコマンド／ショートカット。
4. **結果はどうなるか**: タイムラインが変わる／ファイルができる／情報を見るだけ。
5. **重い処理があるか**: 音声の解析・文字起こし・AI。
6. **誰が使うか**: 自分だけ／ほかの人にも配る。

迷う答えは、例を添えて聞き直す。答えが「それはできない操作」だったら、質問を続ける前に伝える。

### 要望の型 → 雛形と部品

雛形は 4 種類。

| 雛形 | 中身 |
|---|---|
| `panel` | パネルだけ（いちばん小さい形）。ログ・Premiere 操作の型・見た目・診断ボタン入り |
| `panel-commands` | パネル＋メニューのコマンド（パネルを開かずに実行。Mac はキーの割り当てができる） |
| `panel-server` | パネル＋手元のサーバー（音声の解析・ファイルの生成・AI など、重い処理） |
| `cep-helper` | 上に CEP の補助（再生・停止・分割。上級。UXP で足りないときだけ。期限つき） |

| 要望の型 | 雛形 ＋ 部品 | 補足 |
|---|---|---|
| 選んだクリップに効果・位置・大きさを付ける、キーで動かす | `panel` ＋ `ppro-kit`（`motion-bake` が必要なら足す） | 補間を焼き込む（`ref-keyframe-interpolation`） |
| マーカーを付ける・チャプターを作る | `panel` ＋ `ppro-kit` | |
| コマや画面を書き出して見る | `panel` ＋ `ppro-kit` | 書き終わるのを待つ |
| 無音カット | `panel-server` ＋ `silence-cut` | FCP XML を作り直して新しいシーケンスに出す。最低版 26.2 |
| 字幕（文字起こしと SRT） | `panel-server` ＋ `transcribe-srt` | 重い依存が入る。許可を取る |
| テロップのデザインを一括で差し替える | `panel-server` ＋ `mogrt-text` | 最低版 26.2。図形やテキストを新しく作る API は無い |
| メニューのコマンド・ショートカット化 | `panel-commands` | Premiere の画面からは割り当てられず、Mac はシステム設定のアプリのショートカットで割り当てる |
| 分割（レーザー）・再生・停止 | `cep-helper` | 期限つき（CEP は 2028-12 に既定で無効の予定）。分割は実機未確認 |
| 手元で重い処理をしたい（音声の解析・生成） | `panel-server` ＋ `media-tools` など | ffmpeg が要る |
| 鍵を持つサービス（AI など）につなぐ | `panel-server` ＋ `keychain` | 鍵は OS の保管庫に |
| AI（Claude Code / Codex）から操作したい | `panel-server` ＋ `mcp-bridge` | 開発中の確かめにも使える |
| 配る | `packaging` | `make_ccx.py` と合わせる（`core-versioning-release`） |

組み合わせた部品の依存（例: `silence-cut` は `fcpxml` と `media-tools` を必要とする）は、`add_part.py` が追加する。

### 最低版の決め方

使う API のうち最低版が一番新しいものに合わせる（`core-versions`）。特別な API を使わなければ 25.6。FCP XML を使うなら 26.2。聞き取りの段階で、おおよその最低版を利用者に伝える。

### 計画に書くこと

作るもの／使う雛形と部品／最低版／必要な権限（`core-manifest-permissions`）／確かめ方（`core-verification`）／できないこと（と代わりの手）。承認をもらってから、作業フォルダを作る。

## やってはいけないこと

- 質問をまとめて投げる。
- できない操作を黙って別のもので代用する。
- 計画の承認を取る前に作り始める。
- 配るかどうかを聞かずに、配布の設定（版数・パッケージ）を後回しにする。

## 出どころ

- キットの設計（聞き取りの 6 つの質問、実現性の判定、計画の承認の流れ）
- Cut & SRT・Effect & Design・小型 UXP プラグイン 4 本の機能の分類
- 雛形と部品の一覧（キットの `templates/` と `parts/`）
- この知識はキットの設計に基づくもので、実際の聞き取りでの運用は、まだ確かめていない
