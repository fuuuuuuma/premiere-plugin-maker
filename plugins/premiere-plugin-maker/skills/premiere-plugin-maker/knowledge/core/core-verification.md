## 要点

- 「完成しました」「動きます」と言ってよいのは、目的の操作を利用者の Premiere で確かめた後だけ。テストが全部通っても、実機で動いた証拠にはならない。
- 実装の前に、診断ボタン（probe）で、使う API がその Premiere に本当にあるかを調べる。公式の文書にあっても、実装されているとは限らない。
- 何が起きたかは、画面操作ではなくログで確かめる（`logs.py`）。見た目は、書き出したコマを自分で見る。
- 利用者にお願いする操作は 1 回に 1 つ。結果を聞いてから次へ進む。
- 確かめていないことは「未確認」と書く。確かめた範囲と、確かめていない範囲を分けて伝える。

## 詳しく

### なぜ実機なのか

Premiere の UXP や CEP は、手元の Node やブラウザとは別の環境で動く。実際にあった例:

- 文字を揃える機能のテストが 19 本全部通ったのに、実機ではパネルが起動しなかった。
- ブラウザの下見では出ない画面の崩れが、UXP でだけ出た。
- CEP の画面で、読み込みの書き方（UMD）の判定が実機でだけ逆に働き、「読み込んでいます…」のまま固まった。外部プログラムを呼ぶ非同期の関数（`child_process`）は、コールバックが永遠に来なかった。
- テスト用の偽物（スタブ）が、実機に存在しないプロパティを持っていたせいで、テストが誤りを固定していた（フレームレートを黙って 30 に落とす事故）。

テストは「部分的な確認」と位置づける。伝えるときは「ロジックはテストで確認した。Premiere での起動と統合動作は未確認」のように、範囲を分ける。

### 確かめる順序

1. **読み込み**: UDT で Load して、パネルが開くかを見る（`core-dev-loop`）。
2. **診断**: 診断ボタンを押し、使う API の有無・Premiere の版・ログの置き場を表示する。結果を貼ってもらい、API が無いなら実装を変える。雛形には診断ボタンが入っている（`PPM.probe.run(["クラス.メソッド"])` で調べたい API を足せる）。
3. **観察**: プラグインは自分のログを、プラグインのデータフォルダの `ppm-log.txt` にも書く（OS に関係なく読める）。`logs.py` が、このファイルと、Mac の UXP ログ（`~/Library/Logs/Adobe/Adobe Premiere Pro 2026/UXPLogs_*.log`）の、プラグインの印の行を読む。Windows の Premiere 製品版の UXP ログの場所は、公式資料で見つからなかった。
4. **画で確かめる**: 見た目を判定するときは、プレイヘッドをその時刻に置いてから、シーケンスのコマを書き出して見る。置かずに書き出すと、上のトラックのグラフィックが落ちることがあった。アニメは書き出して一定間隔で抜き、**抜いた画像は全部見る**。見た分だけを「確認した」と言う。
5. **利用者にお願いする操作は 1 回に 1 つ**。結果（スクリーンショットやログ）を受け取ってから次へ進む。
6. **「完成」の報告**: 目的の操作を利用者の Premiere で確かめた後だけ。

### 診断の判定

実機の診断は、「呼べたか」ではなく、**戻り値と状態の変化**で判定する。例えば効果を足す呼び出しは、例外が出なくても、戻り値と部品の数が増えたかで確かめる。診断で危険な段（MOGRT の挿入など、Premiere を固める可能性があるもの）は既定でオフにして、1 つだけ選んだときに実行する。診断の結果は表にして残し、ログの実物を貼らずに「動く」と書かない。

### 似た経路で測らない

不具合の確認は、実際に壊れている経路で行う。似た経路や、模擬の素材、単体テストで通っても、本物の証拠にならない。直したあと、報告された操作そのものを再現して確かめる。欠陥を見つけて直したことと、症状が消えたことは別。「根治」は、実機で症状が消えてから書く。

### 実機を共有する作業のマナー

- 利用者のプロジェクトを守る。確かめる専用のプロジェクトとシーケンスで、既存のトラックを使わない。
- 画面操作（Claude による画面の操作）は、利用者の作業を止めるので、ログやテストで判別できない見た目の確認だけに使う。使う前に一言断る。
- 作業を AI に任せるときは、本物の資格情報の保管庫などに触れないよう指示に書き、終わった後に痕跡を点検する。

## やってはいけないこと

- Node のテストやブラウザの下見だけを根拠に、「動作します」と言う。
- 公式の文書にあるだけの API を、診断なしに採用する。
- 切り出した画像のうち、一部しか見ていないのに「全部確認した」と言う。
- 「直ったはず」と言って、利用者に確認を委ねる前に報告を終える。
- 確かめていない手順を、動くと言う。
